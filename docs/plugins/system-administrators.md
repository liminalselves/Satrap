# 系统管理员与插件管理权限

在“系统设置 / 管理员”中创建管理组, 添加管理员的平台实例与平台用户识别号, 再选择适用插件. 同一用户在不同平台上的身份分别保存; 群主或平台管理员角色不会自动成为 Satrap 系统管理员

授权分三层, 自底向上: 插件本地名单, 管理组与成员例外. **组只负责授予, 人只负责例外**. 任一层出现否决或排除时, 都压过所有允许

每组可以启停, 修改成员, 选择指定插件或所有已接入插件. 指定插件模式只表达允许, 不再携带排除; 所有插件模式为全集减去排除项, 包含以后接入该机制的插件. 多组允许范围取并集

成员例外是新增的对人裁决层, 按平台实例与用户识别号定位. 它可以额外允许某个不属于任何管理组的人, 也可以否决某个组已授予的插件, 两者都支持. 组与例外各自带账号保护开关, 组成员缺省受保护, 例外条目缺省只调整授权

配置默认没有管理组与成员例外. 未配置或停用全部条目后, 原插件行为保持一致. 未接入权限声明的插件不会因被选中而获得额外权限

## 保存与生效

首次升级到包含本功能的版本时, 需按原启动方式重新启动控制服务, 并启动使用新代码的后端, 然后刷新页面. 已经运行的旧控制服务不会自动加载新增接口; 仅刷新浏览器或重启平台后端不足以更新控制服务

管理员页独立保存同一配置文件中的 administrator_groups 与 administrator_overrides 区段, 无需重启后端. 页面区分“已保存并生效”, “已保存, 后端启动后生效”和“已保存, 无法确认运行时生效”; 未确认时可重试应用已保存配置

配置冲突返回错误并保留草稿. 可以保留草稿读取最新版本, 比较最新管理组后再次保存. 切换设置页签和刷新目录不会丢失管理员草稿

平台实例删除重建后, 原身份显示失效. 点击“绑定到当前平台”后保存才会重新授予该身份权限. 仅修改客户端内部实例 ID 不会重新授权

## 从旧配置迁移

旧版本允许在指定插件模式下填写排除列表, 且排除作用在组成员上. 新模型不再支持新增这种写法, 读取配置时会在内存中自动展开: 把每个组的旧排除转成该组当前成员的成员例外否决, 并清空组的排除列表, 界面上会提示发生过迁移

迁移只在内存生效, 下次保存时落盘. 展开按保存时的成员名单执行, 之后新加入该组的成员不会自动继承这条否决, 需要重新在成员例外中添加. 所有插件模式下的排除不受影响, 仍留在组内

存量配置的旧排除在迁移完成前可经任意保存路径原样往返, 逐项移除也允许; 但手工新增“指定插件模式的排除”会被严格校验拦下并返回 400, 新否决请改用成员例外

停用组的旧排除迁移后得到的是停用例外条目, 之后**启用该组不会恢复这条旧排除**, 需要单独启用对应例外条目

如果某个成员已有例外条目的启用状态与源组不一致, 该组会整体跳过迁移并保持旧排除原样, 界面提示冲突的管理组; 调整对应例外条目的启用状态后下次读取即可完成迁移

## 本轮支持的插件

| 插件 | 管理员可免填的名单 | 仍需满足 |
| --- | --- | --- |
| group_chat | cross_group_query_callers, nickname_allowed_callers | 私聊群列表范围; 自身群昵称修改开关, 当前群和宿主审批 |
| group_admin | allowed_read_callers, allowed_callers, request_managers | 管理写开关, 群范围, 机器人平台权限与动作审批 |
| friend_manager | managers, write_callers | 私聊范围, 对应好友写开关, 账号保护; 删除好友固定待人工批准 |

页面逐项展示插件接受的管理权限及业务条件. 管理员不会自动开启插件或工具, 不会跳过功能开关, 平台能力, 成员所有权和审批. 开启账号保护的管理组成员与成员例外身份加入对应平台的好友删除保护, 与已有保护名单取并集

真实身份从入站消息取得, 不需要模型填写发言者 QQ 号. 工具参数中的目标 user_id, 昵称, 被 @ 的对象和模型输出都不能冒充管理员

移除成员, 停用管理组或成员例外, 或者否决某插件并成功应用后, 后续调用与待审批动作重新检查当前权限. 如果原插件名单仍授权该成员, 操作可以沿原名单路径继续; 否则未执行动作被拒绝

## 插件开发接入

使用 meta.yaml 显式声明 management_permissions, tool_permissions 与 command_permissions. 权限支持本地名单规则, 空值规则与 system_admin 标记; 多项入口权限全部满足, 每项权限内部采用“本地名单允许或管理组与成员例外授权”

requirements 只显示业务条件说明, 不决定是否允许执行. 业务功能仍由插件与宿主服务校验. 插件之间不读取其他插件配置, 统一权限服务由宿主提供

没有声明的旧插件保持兼容. 非法声明拒绝加载, 在管理员页显示原因并记录后端日志; 不退化成允许, 不中断其他插件与平台进程

本轮保留原生命令与子命令的权限绑定接口, 尚未新增业务审批命令. 群记忆本人所有权, 共享记忆提案及编程插件执行权限机制不随管理员授权放宽

声明字段, 判定规则与宿主接口见 [插件系统: 管理权限声明](../edictum/plugin-system.md#管理权限声明-可选)

## 配置结构与接口

管理组与成员例外保存在后端配置文档的 `administrator_groups` 与 `administrator_overrides` 区段, 页面编辑即可, 无需手写:

```yaml
administrator_groups:
  - id: primary-admins
    name: 主要管理员
    enabled: true
    protect: true             # 成员是否进入好友删除保护名单, 缺省为真
    members:
      - platform_id: onebot-main
        platform_instance_id: 由服务保存时绑定
        user_id: "10001"
    plugin_scope:
      mode: selected            # selected 只允许; all 只排除
      included: [group_admin, friend_manager, group_chat]
      excluded: []
administrator_overrides:
  - id: intern-zhangsan
    enabled: true
    protect: false            # 例外缺省不加入保护名单
    platform_id: onebot-main
    platform_instance_id: 由服务保存时绑定
    user_id: "10002"
    allow: [group_chat]       # 额外允许, 可空
    deny: [group_admin]       # 否决, 可空
```

指定插件模式下填写排除列表会被保存接口拒绝, 请改用成员例外. 例外条目同时允许与否决同一插件不会导致配置被拒绝, 求值按否决优先, 后端记录一条误配日志

`platform_instance_id` 由服务端按所选平台实例绑定, 不接受前端指定; 授权同时匹配入站来源的平台 ID, 用户 ID 与该实例 ID

控制服务接口沿用现有鉴权:

| 接口 | 用途 |
| --- | --- |
| `GET /config/administrator-groups` | 读取管理组与成员例外, 配置 revision, 迁移标记与运行时应用状态 |
| `PUT /config/administrator-groups` | 提交完整 `groups` 与 `overrides` 及 `expected_revision`, 只更新这两个区段; 版本冲突返回 409, 结构或身份错误返回 400 |
| `POST /config/administrator-groups/apply` | 将已保存的指定 revision 应用到运行中的后端 |
| `POST /config/administrator-groups/preview` | 校验草稿并返回各身份的有效插件范围与来源归属, 不保存不授权 |
