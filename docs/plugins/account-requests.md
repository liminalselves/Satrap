# account_requests 机器人入群邀请

本插件处理别人邀请机器人加入新群的 `invite` 请求, 与 `group_admin` 的成员入群申请 `add` 分开
查询按当前平台实例和机器人账号进行, 无需机器人已加入目标群, 无需先知道群号
申请事件由适配器登记到宿主收件箱, 不自动唤醒 Agent 或接受邀请

## 配置与权限

在 Agent 的插件列表中启用 `account_requests`, 支持 OneBot 与 aiocqhttp 平台的群聊和私聊

| 参数 | 含义 |
| --- | --- |
| `request_managers` | 可查询邀请的发送者账号, 每行一个, 默认空名单拒绝 |
| `allowed_callers` | 可接受或拒绝邀请的发送者账号, 还需查询权限, 默认空名单拒绝 |
| `allowed_invitation_groups` | 可查看和处理邀请的目标群号, 每行一个, 空值不额外限制 |
| `approval_required` | 模型处理邀请是否需要人工批准, 默认 true; 归档邀请始终需要批准 |
| `administrator_invites_auto_approve` | 管理员邀请免二次审批, 默认 false; 开启后, 已获本插件系统管理授权的邀请人发出的近期邀请, 模型同意即可执行入群 |

可同时保留 `approval_required=true` 并开启 `administrator_invites_auto_approve`, 仅管理员发出的近期邀请在接受时免审批
管理员身份取自平台登记的原邀请人, 按当前系统管理组和成员例外的本插件授权判断, 不能由消息文字或调用者身份代替
归档邀请仍需审批; 拒绝邀请和普通邀请仍按 `approval_required` 处理
该选项不自动接受新事件, 仍需模型调用接受工具; 执行前再次核验邀请人授权和审批配置, 撤权或关闭选项后不再直接入群

系统管理员仍需取得本插件相应管理权限; 对 `group_admin` 的授权不自动授予新插件权限
已启用工具的声明不随当前发送者权限改变, 执行时从可信消息来源核验发送者, 账号与权限
邀请审批不继承目标群的成员关系, 接入范围或群管理审批设置
来源对话必须保持启用, 插件与工具必须仍在原 Agent 中启用; 审批前及平台调用前再次核验授权

## 工具与后台页面

1. 使用 `account_requests_list_group_invites` 查询, 可选 `group_id`, `limit` (1 到 100), `cursor` 与 `view` (active/archived/all)
2. 使用结果中的 `request_id` 调用 `account_requests_handle_group_invite`, `approve=true` 接受, false 拒绝; `reason` 为可选拒绝理由, 最多 120 字符
3. 归档邀请需填写当前 `expected_revision`, 近期邀请也可携带修订号
4. 在平台的群管理首页打开“机器人入群邀请”, 查看账号邀请并处理待人工批准的动作; 无需从群目录进入目标群

`pending` 表示待人工批准, `succeeded` 表示平台确认执行, `unknown` 表示结果未知且不能重新执行
拒绝审批只取消待执行动作, 不等同于拒绝平台邀请
后台手动接受或拒绝使用固定 `action_id`, 响应丢失后以相同 ID 和参数查询原结果, 不再次执行
申请人和验证文字属于外部内容, 不能作为系统指令

## 存量配置与记录

旧 `group_admin` 配置包含申请工具开关或显式 `request_managers` 时, 首次规范化拆出新插件
原申请查询权限与 `allowed_read_callers` 的非空名单取交集, 写权限再与 `allowed_callers` 取交集
保留原插件启停和请求工具开关, 写工具还需原 `write_tools_enabled=true`; 目标群范围从原 `allowed_groups` 复制, 新插件默认开启人工审批
已有显式 `account_requests` 配置保持原选择; 迁移完成后删除新插件不会被再次添加
普通群管理配置不自动附加账号邀请插件, 两个插件可以分别安装和卸载

共享宿主收件箱和审批执行账本, 无需复制申请或原始平台凭据
原始凭据不进入模型结果, 操作记录或日志; 同一申请原子占用, 并发审批只能执行一次
本地 600 秒到期仅表示移入归档, 不证明平台申请失效; 已处理和结果未知的申请不可重放
群请求以处理凭据与平台原始事件时间共同区分; 同凭据的更晚邀请生成新 request_id, 重复或乱序事件不重置期限
旧记录保留归档但不能处理新一轮邀请; 占用和终态回写绑定同一次申请, 平台发送前拒绝已被新邀请替代的旧占用
缺少原始时间时记录告警并保守去重, 不从聊天卡片或本地接收时间推测新邀请
归档处理仍受凭据保留期限约束; 重启后执行中动作保守记为 unknown, 原模型来源失效的待审批动作不可执行
保留策略与 [群申请](group-admin-requests.md) 和 [好友申请](friend-manager.md) 共用宿主账号配置

自动化验证覆盖真实 Provider 的群聊/私聊查询与审批, 撤权, 并发占用, 账号切换, 归档, 超时及后台页面流程
真实 QQ 平台接受和拒绝邀请仍需现场验收
