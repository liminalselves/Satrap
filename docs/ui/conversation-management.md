# Agent 配置与对话记录

管理面板将定义 Agent 和维护已保存对话分成两个入口:

- **Agent 配置** (`/agents`): 管理会话类模板、模型绑定与 Edictum 执行流程; 此处配置描述如何创建和运行 Agent
- **对话记录** (`/conversations`): 按平台浏览、搜索已保存的对话, 查看和修改其上下文或 Chat 展示历史
- 对话记录中的 **管理对话实例** (`/conversations/instances`): 保留平台实例的运行状态、插件覆盖、删除和手动唤醒功能
- 对话记录中的 **版本与恢复** (`/conversations/versions`): 查看检查点、分支、变更记录与血缘, 创建快照、恢复消息上下文或派生分支

旧链接 `/sessions` 和 `/checkpoints` 仍可访问, 分别跳转至 Agent 配置和版本与恢复, 保留查询参数; 带群筛选参数的旧会话链接跳转至对话实例. `/users` 跳转至对话记录的用户视图, 保留平台和用户选择

## 按用户浏览

对话记录提供“按对话”和“按用户”两个视图, 共用动态平台类型和实例筛选. 用户以平台实例与用户 ID 共同定位, 不根据昵称或相同 ID 合并不同平台的用户. 已保存但未运行的平台仍可浏览, 没有对话的用户资料也保留

点击用户查看本地资料和关联对话, 点击“查看对话”进入原有上下文和历史编辑区域. 用户关联来自保存的用户列表或精确路由归属, 群共享路由不推断个人归属. 仅有路由但没有资料的用户标明“未保存用户资料”, 不存在的旧列表关联标明“对话不存在”

“编辑用户资料”只修改本地昵称, 不更改平台账号资料或跨平台搬迁用户. 高级操作可以添加或移除当前平台已有对话的列表关联, 不改写平台实际路由. 本地按用户选择会话的调用可能使用此列表, 因此列表关联变化可能影响这类调用

“删除用户资料”删除昵称和列表关联, 不删除对话、消息或实际路由. 后续消息可能重新创建资料. 删除对话和历史仍使用各自明确标明影响范围的入口

用户目录查询不创建数据库或迁移表. 修改用户资料使用事务及资料版本校验, 过期修改返回冲突并保留表单草稿; 服务失败记录日志且隔离单次请求

用户目录接口为 `GET /config/conversations/users`, 支持 `platform_id`, `platform_type`, `q`, `offset`, `limit`; 指定 `platform_id` 与 `user_id` 查询单个用户. `POST` 同路径携带 `action`, `platform_id`, `user_id`, `expected_revision`, 支持 `create`, `update`, `delete`, `associate`, `dissociate`. 创建时使用目录返回的 `new_revision`, 其它操作使用用户记录的 `revision`

## 两份数据的影响范围

| 数据层 | 内容 | 修改影响 |
|---|---|---|
| 上下文 | 保存的模型消息, 包括提示词、多模态内容、思考和工具调用 | 改变机器人后续使用的上下文; 不改写 Chat 展示历史 |
| Chat 展示历史 | Chat 页面录制的用户输入、助手回复、思考、回复版本和工具明细 | 只改变 Chat 页面展示; 不改写模型上下文 |

平台选择器包括 Chat、本地和已有数据目录的平台实例。工作流可能拥有多份上下文, 使用“上下文范围”选择主上下文或处理器上下文。非 Chat 平台没有此处独立的 Chat 展示历史, 其“Chat 展示历史”按钮禁用

上下文页显示完整保存消息。最终模型请求还可能经过截断、总结或临时提示注入, 所以此页不能据此推断某次请求实际发送的全部参数, 也不展示请求的 `tools` 定义。临时注入的系统提示词可能不在保存消息中

## 查看、修改与删除

1. 选择平台, 按对话 ID、上下文 ID 或 Chat 首条输入搜索, 从列表选择对话
2. 选择数据层; 查看普通文本, 或展开“原始数据与结构字段”核查多模态、工具调用和回复版本
3. 点击条目的“编辑”, 修改内容后保存; 保存失败保留草稿并显示原因, 离开未保存表单前需要确认
4. 点击“删除”移除条目, 或使用清空操作。清空上下文默认保留 `system` 和 `developer` 提示词, 可以取消勾选一并清空

上下文编辑只允许修改消息内容与思考文本, 角色、工具调用 ID 和调用结构保留。内容支持文本、多模态 JSON 数组及 `null`。删除工具调用消息或某个工具结果时, 会一起删除所属助手调用及其全部结果, 防止留下不完整工具调用组

历史编辑修改当前显示轮次和其活动回复版本, 保留其他回复版本和工具明细。删除历史轮次会一起删除该轮次的回复版本和工具明细; 模型上下文保持原样

## 并发与恢复

活动实例通过运行服务的操作锁读取或修改, 保存后同时更新数据库和内存; 本轮正在生成、实例正在激活或同一上下文被多个实例共享时会拒绝操作。未激活对话的查看或修改不会创建 Agent 实例

保存请求带读取时的内容版本。数据变化后返回冲突, 此时重新读取并合并草稿, 避免覆盖期间新增的消息。只有运行服务明确拒绝连接时, 控制服务才直接访问对应平台数据库; 超时、鉴权失败和服务内部错误不会触发此回退

每次编辑、删除、清空或恢复都在同一数据库事务内保存修改前的完整数据, 失败时整体回滚。“修改备份与恢复”展示当前数据层最新 50 份备份; 恢复只作用于当前对话和数据层, 并备份恢复前的状态。备份不会自动清理, 删除的内容仍可能存在于备份中。归档与还原对话时也会包含这些备份

上下文修改会清除失效的总结状态及依赖旧消息顺序的指针检查点, 已物化的检查点保留。“版本与恢复”的恢复操作仅替换消息上下文并生成修改备份, 不覆盖独立展示历史或其他状态域

## 管理接口

控制服务提供统一入口, 使用现有管理鉴权:

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/config/conversations/platforms` | 可选平台 |
| GET | `/config/conversations?platform_id=chat&q=关键词&offset=0&limit=40` | 对话列表 |
| POST | `/config/conversations/data` | 读取或修改指定数据层 |

数据请求必填 `platform_id`、`conversation_id`, `layer` 为 `context` 或 `history`, 读取支持 `offset` 和 `limit`。写请求另带 `expected_revision` 及 `action`: `edit`、`delete`、`clear`、`restore` 或上下文专用的 `checkpoint`

控制服务将活动数据操作转发到后端 `/api/conversation-data` 或 Chat `/api/chat/conversation-data`。请求无效、数据缺失、冲突和内部失败均返回明确错误并记录日志, 内部异常包含堆栈
