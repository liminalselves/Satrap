# 系统管理员与插件授权计划

日期: 2026-10-06

状态: 实施中; 权限核心已接入, 业务迁移和设置界面尚未完成

## 1. 目标与范围

在系统设置增加“管理员”页签, 保存管理员的平台与平台用户识别号, 通过管理组指定其自动获得哪些插件的管理身份. 获授权的管理员无需重复填写各插件的调用者名单

第一步接入既有 group_chat, group_admin 与 friend_manager 的调用者校验. 未来的群记忆, 群动作及好友删除审批命令使用同一宿主授权服务; 本次不顺带实现这些新命令, 不修改编程插件的执行权限机制

“自动放行”指调用者名单检查通过. 功能启停, 工具启停, 对话范围, 平台能力, 来源校验, 所有权和逐次审批继续生效

## 2. 前端结构

系统设置 / 管理员支持新增, 修改, 启停和删除管理组. 每组显示名称, 成员, 插件范围及实际授权预览

| 字段 | 控件与含义 | 默认 |
| --- | --- | --- |
| 管理组名称 | 可读名称, 内部使用独立稳定 ID | 新建时填写 |
| 启用 | 控制这一组是否参与授权 | 开启 |
| 管理员成员 | 可添加多条“平台 + 平台识别号” | 空, 不授权任何人 |
| 平台 | 从已配置的平台实例中选择, 显示实例名称与适配器类型 | 必选 |
| 平台识别号 | 此管理员在所选平台的用户 ID; QQ 平台填写成员 QQ 号 | 必填字符串 |
| 适用插件 | “指定插件”或“所有已接入插件”; 指定模式可多选 | 指定插件, 空选择 |
| 排除插件 | 多选, 阻止这一管理员身份在所选插件自动放行 | 空 |
| 授权预览 | 展示此组实际覆盖哪些平台成员, 插件及管理入口 | 只读 |

平台和插件列表从目录接口动态取得. 插件未安装或暂不可用时保留原选择并显示状态; 未接入管理员授权的插件显示“未接入”, 不声称其已获得权限. “所有已接入插件”会包含未来声明接入的插件, 界面明确说明这一行为

管理员识别号使用字符串保存, 校验通过适配器提供的通用身份规范接口完成; 不在共享设置中写死 QQ 数字规则. 平台名相同但实例不同的成员授权分别保存. 一个实际用户可通过多条平台身份加入同一组

## 3. 数据与身份契约

管理员配置使用现有系统配置文档的 `administrator_groups` 区段, 不创建新的散落配置文件. 结构为:

```yaml
administrator_groups:
  - id: primary-admins
    name: 主要管理员
    enabled: true
    members:
      - platform_id: onebot-main
        platform_instance_id: 由服务保存时从所选实例绑定
        user_id: "2410323775"
    plugin_scope:
      mode: selected
      included: [group_admin, friend_manager, group_chat]
      excluded: []
```

示例 ID 仅为结构说明. 前端填写平台和用户 ID 后, 服务端绑定真实 instance_id; 不接受前端指定任意实例代次. 授权匹配当前真实 CallOrigin 的 adapter_id 与 actor_id, 并验证所选平台的持久 instance_id. 同一平台注册 ID 被删除后重新创建, 旧授权显示失效, 必须明确重新绑定

昵称, 群昵称, 被 @ 的对象, 工具参数 user_id 和模型输出都不能作为管理员身份证明. 权限在操作入口从最新配置计算, 不缓存在共享 Agent 或写入模型可修改的参数

## 4. 插件范围合并与授权结果

1. 仅考虑启用且命中当前平台成员身份的管理组
2. 合并这些组允许的插件; 任一命中组排除某插件时, 排除优先, 该成员不获得此插件的系统管理员自动授权
3. 排除只撤销系统管理员自动授权. 插件自身显式名单仍可独立授权, 不把管理组排除项扩展成全局封禁
4. 插件必须声明支持的管理员授权入口. 未接入的插件不因被选中或使用所有模式而自动获得权限
5. 现有管理员配置缺失或列表为空时, 完全沿用各插件现有行为

调用者校验的核心契约:

```text
有效调用者授权 = 插件原有名单判断通过 OR 当前成员获得该插件的系统管理员授权
允许执行 = 有效调用者授权 AND 此操作的其他必要条件全部通过
```

原有空名单语义保持: allowed_read_callers 或 nickname_allowed_callers 为空仍按既有规则不额外限制. 系统管理员排除不会把这种原有允许改成拒绝

## 5. 本轮接入的入口

| 插件 | 自动满足的名单检查 | 继续要求的条件 |
| --- | --- | --- |
| group_chat | cross_group_query_callers | 群列表查询仅私聊, 只列可访问范围 |
| group_chat | nickname_allowed_callers | self_nickname_enabled, 当前群, 只能修改机器人自己, 宿主审批 |
| group_admin | allowed_callers | write_tools_enabled, 目标范围及平台权限, 宿主与插件审批 |
| group_admin | allowed_read_callers | 目标范围, 来源归属及读取能力 |
| group_admin | request_managers | 查询 / 处理申请的其他校验; 处理还须写开关与写授权 |
| friend_manager | managers | 仅私聊, 同一机器人账号及好友能力 |
| friend_manager | write_callers | managers 检查也通过, 对应写开关, 目标保护及删除审批 |

第一步不改变 memory 模型工具的所有权契约: 本人偏好只能由本人通过模型修改; 共享群记忆仍提交提案. 后续人工命令可根据系统管理员对 memory 的授权执行审批与管理, 不能把“管理员发言”变成模型直接修改他人偏好的捷径

系统管理员账号纳入对应平台的宿主好友删除保护, 与既有保护名单取并集; 限启用管理组和有效的平台身份. 保护身份不因某组排除 friend_manager 而自动消失

## 6. 宿主授权接口与插件独立性

新增独立的宿主管理员授权服务, 接受可信来源与插件名称, 返回允许 / 不允许, 命中的管理组和配置 revision. 插件只向宿主查询自己的授权, 不读取其他插件配置

为插件目录增加管理员授权声明, 描述可接入的调用者门槛和未来命令权限. 插件名称和能力从目录取得; shared 服务不硬编码平台或四个业务插件的名称列表

已接入插件在工具声明过滤, 执行入口, 等待后的复核及持久申请执行前统一使用该服务. group_admin / friend_manager 的来源权限指纹纳入有效管理员授权, 避免出现“工具允许提交, 后端却按旧名单拒绝”的两套判断

管理员被移除, 管理组关闭, 插件被排除或平台重新绑定后, 未执行动作复核最新授权. 若插件自身名单仍允许, 可以沿原授权继续; 若授权已撤销, 拒绝执行. 相关权限范围变更导致旧申请指纹失效时, 明确提示重新提交

审计记录真实发言者, 平台实例, 插件, 操作及授权来源; 系统管理员路径记录命中的管理组. 业务审批继续区分请求者和审批者, 不统一标记为模型或 authenticated_operator

## 7. 保存与运行时生效

现有系统设置通用保存会重启后端. 新管理员区使用独立的保存与应用接口, 更新同一配置文档, 通过 revision 防止覆盖其他配置, 并向运行中的宿主授权服务应用不可变配置快照

保存后显示“已保存并生效”, “已保存, 后端启动后生效”或“已保存, 无法确认运行时生效”, 不因写文件成功就声称权限已应用. 无法确认时展示可重试应用操作. 撤销权限完成应用后, 后续校验使用最新 revision

配置接口使用现有管理服务鉴权; 首批不提供聊天命令修改管理员名单或授权范围. 配置冲突保留编辑草稿, 非法身份 / 结构拒绝并记录日志, 错误由 API 边界捕获
