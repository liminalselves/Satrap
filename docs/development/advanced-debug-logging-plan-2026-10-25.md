# 对象级高级 Debug Logger 与消息链路方案

日期: 2026-10-25

分支: issue-27

状态: 已实施并完成本地验收; 未提交, 未部署, 未迁移业务数据库; Linux/macOS CI 与真实接口尚未验收

实施与实测结果见 [advanced-debug-logging-results-2026-10-26.md](advanced-debug-logging-results-2026-10-26.md)

## 1. 目标与边界

1. 为平台与 Chat 提供可持久查询的完整消息执行链路, 覆盖输入, 模型请求和返回, 工具参数和结果, 审批, 回复与交付
2. 高级 Debug Logger 按稳定对象设置, 群内开启后, /new, /switch, 路由切换, 实例回收与重启均不清除该群设置
3. 提供整体默认和对象覆盖, 前端及原生命令插件使用同一个设置服务
4. 日志监控新增高级 Debug 页面, 以会话上下文为首层浏览索引, 在其下按请求展示链路
5. 采用已验证的明细精简, 消息正文共享和轻压缩, 不把完整历史重复嵌入每个节点

普通运行日志继续记录启动, 连接, 警告与错误; 高级 Debug 开关不改变普通 logger 的级别和文件策略

本轮不新增任意工具执行点 Fork 功能, 不重写已有 RunStore 或业务状态账本, 不修改 Astro 源码和数据库

## 2. 已验证的存储依据

离线对照使用 Astro 的同一份历史样本, 共 440 个 JSON 单元, 原始输入包含当前事件以及快照内的历史版本

| 方案 | 独立链路 SQLite 文件 | 正文及引用元数据 |
| --- | ---: | ---: |
| 原样保存 | 49.983 MB | 49.315 MB |
| 完整资料去重与轻压缩 | 2.761 MB | 1.930 MB |
| 省略拼装明细, 保留版本和摘要水位 | 2.589 MB | 1.805 MB |
| 再合并模型输入并共享相同消息正文 | 2.064 MB | 1.103 MB |

最后一种相比原样保存减少约 95.87% 文件占用, 相比上一轮完整资料去重再减少约 25.22%; 提高压缩等级仅额外减少 4096 字节文件占用

本轮采用最后一种作为设计依据, 默认使用 zlib level 1, 小正文压缩收益不足时保持原文

对照验证全部转换后 JSON 等值还原, 2162 次输入转换验证与 Astro 当前拼装函数生成的消息序列相同; 主动省略的 sections 资料不能再查看, 不声称原始全字段无损

实验没有验证真实 Astro Fork/恢复兼容, 长期增长, 并发或服务器磁盘性能; 2.064 MB 是此样本结果, 不是任意部署的容量承诺

原始指标和实验方法本地留档于 satrap-ui/test-results/event-chain-storage-trim-20261025, 不将其中的用户正文纳入仓库

## 3. 对象设置与上下文索引分开

### 3.1 稳定对象标识

平台对象使用结构化标识, 不解析 session_id 或 scope_ 字符串猜测归属:

| 字段 | 来源与含义 |
| --- | --- |
| platform_id | 已登记的平台实例标识, 区分不同适配器实例 |
| self_id | 实际机器人账号, 区分同平台的不同账号 |
| conversation_kind | 已归一的 group 或 private |
| target_id | 群 ID 或私聊对端 ID |

这些字段在可信入站边界固定, 命令不能通过自报群号或昵称指定另一个对象; 账号身份暂时无法确认时, 不创建可能串号的对象设置

群共享上下文和群内按成员隔离的上下文使用同一个群对象设置, 发话人和 Agent 绑定仅作为索引字段

Web Chat 使用当前 Chat 服务的持久实例命名空间和持久 Chat 会话 ID 作为对象标识; 同一 Chat 对象内部上下文变化继续使用原设置, 新建独立 Chat 或 Fork 新 Chat 对象按整体默认解析, 不复制来源对象的强制开关

### 3.2 上下文标识

独立记录 context_id, 上下文所属对象, 会话标题, 主/子工作流关系和归属版本; 上下文不是开关的存储位置

例如:

```text
群对象 G: debug=on
  上下文 C1: 请求 R1, R2
  /new
  上下文 C2: 请求 R3, R4
```

C1 与 C2 在页面上分别列出, 设置均来自 G; 新上下文不要求用户重新开启 debug

上下文归属使用现有路由和上下文目录注册结果, 老记录无法确认时明确显示未知, 不从名字推测

请求在分配上下文之前被拒绝或仍在排队时, 归入该对象的未绑定上下文分组; 绑定后补充关联, 不因缺少 context_id 丢掉记录

## 4. 默认设置与生效规则

### 4.1 开关三态

| 对象设置 | 生效规则 |
| --- | --- |
| inherit, 继承默认 | 读取当前整体默认值 |
| on, 强制开启 | 不受之后默认值改变影响 |
| off, 强制关闭 | 默认开启时也不记录高级链路正文 |

建议初始整体默认关闭, 需要排查的对象显式开启; 管理面板可开启整体默认, 让所有未覆盖对象生效

默认值是动态继承, 不在对象首次创建时复制一份; 改整体默认会影响已有和未来的 inherit 对象, 不改变明确 on/off 的对象

每个请求在受理时冻结设置值和 revision, 中途修改从下一请求生效, 页面和命令回执明确说明; 子 Agent 继承所属请求的记录策略

关闭不删除已有记录, 清理是独立操作; 关闭高级记录不影响普通 WARNING/ERROR, 任务恢复, 命令上下文可见性或审批策略

### 4.2 持久化位置

使用 .satrap/config/debug_logging.json 保存整体默认, 容量策略和对象覆盖, 复用配置修订, 文件锁和原子保存

对象覆盖按完整结构化身份保存, 不放入当前 Session 临时 config, 会话缓存目录或 conversation_meta 的上下文级字段

读路径缓存已解析的设置, 原子文件替换后按文件变化刷新; 不在每条事件写入时读取并加锁整个配置文件, 不跨模型/工具等待持有配置锁

设置保存返回 revision; 并发修改按现有配置版本冲突回执处理, 不静默覆盖另一页面或命令的修改

跨进程设置变更在下一请求解析时检查最新文件版本; 缓存只减少解析成本, 不允许无限期沿用旧开关

### 4.3 建议初值

| 参数 | 建议初值 | 说明 |
| --- | --- | --- |
| default_enabled | false | 未覆盖对象默认不开启高级正文记录 |
| retention_days | 7 | 已结束诊断链路的保留期 |
| max_total_mb | 512 | 本部署各服务高级日志合计目标容量, 前端显示 MB |
| max_body_mb | 8 | 单份原始正文的采集上限, 超限保留明确截断说明 |
| max_request_mb | 32 | 单请求原始正文采集预算, 不按压缩比放大限制 |

这些是待基准校准的初值, 不以其宣称严格磁盘硬配额; WAL, 活跃请求与维护临时空间单独计量和限制

容量到限先清理到期和最旧已结束链路; 活跃链路不被整条删除, 无法释放时停止新增正文并保留有界状态摘要, 标记不完整, 不阻塞业务

## 5. 原生命令插件

新增内置 debug_logger 命令插件, 命令名 /debug; 插件只提供命令入口, 不导出模型工具, 不提供让模型替用户改开关的服务

| 命令 | 作用 |
| --- | --- |
| /debug status | 查看当前对象设置, 生效值, 来源, 当前上下文与 revision |
| /debug on | 将当前对象持久设置为强制开启 |
| /debug off | 将当前对象持久设置为强制关闭 |
| /debug reset | 删除当前对象覆盖, 恢复继承整体默认 |
| /debug default status | 查看整体默认及其修订 |
| /debug default on | 修改整体默认为开启, 需要全局管理权限 |
| /debug default off | 修改整体默认为关闭, 需要全局管理权限 |

不开启通过命令填写任意目标 ID 的跨对象修改, 跨对象管理使用面板选择明确对象

同步与异步命令都通过 plugin_host.debug_logging 的窄接口取得可信对象与设置服务, 实际授权在宿主校验; 不直接导入其它插件私有实现

沿用 requires_native_scope 的原生命令约束和现有系统管理授权; QQ 原生群管理员身份不自动等同于系统管理员, 已授权群内管理范围按现有后端规则判断

普通成员不能开启群级日志或查询其它对象内容; 拒绝时返回明确权限原因, 不改用工具路径执行

命令设置的控制面只依赖服务状态, 不依赖当前对象已开启高级 logger; 安装与默认启用范围需覆盖内置平台/Chat 会话, 被用户禁用的命令插件不被自动复活

卸载命令插件仅移除命令入口, 不清空已保存设置或日志; 宿主和面板继续能管理

/debug 开关修改始终记录最小配置审计, 包含真实操作者, 对象, 旧值, 新值与时间; 不把其它消息正文带入该审计

开关命令不调用 LLM, 不自动改变命令是否写入模型上下文的现有选项

回执示例:

```text
本群高级 Debug 已开启, 从下一请求生效
设置绑定本群, /new 后继续生效
```

## 6. 统一执行事件与已有恢复记录协作

复用已有 request_id, run_id, model step, tool_call_id, 展示版本与发送回执标识; 新增事件 ID 和父子节点关系用于展示, 不改写业务标识语义

执行边界生成带明确类型的事件, 分别送往已有业务记录入口和诊断记录入口; 不在插件之间叠加通用执行 Hook, 不覆盖 DisplayRecorder 的单槽观察回调

已有 RunStore 继续决定任务恢复与副作用确认, 其必要写入和错误处理保持原语义; 高级 logger 读取同一事实的诊断投影, 写入失败不阻断模型或工具

同一调用事实只在实际执行边界采集, 不由模型文本, 最终聊天历史或当前上下文反推

| 阶段 | 保存内容 |
| --- | --- |
| 入站 | 来源对象, 发话人, 消息 ID, 正文及附件引用 |
| 唤醒与排队 | 是否受理, 拒绝原因, 排队起止与耗时 |
| 投影与上下文准备 | 本轮投影输入, 引用/媒体处理结果, 摘要水位, 处理策略与版本 |
| 模型开始 | 本次实际客户端和模型, 最终生效的 messages, 工具定义与必要请求参数, 超时配置 |
| 模型结束或中断 | 文本, 结构化工具请求, finish_reason, Token 用量, 首字及总耗时, 错误资料 |
| 工具开始与结束 | 插件和工具, call_id, 实际参数, 返回值, 调用异常与业务结果分别表示 |
| 审批 | 待审批, 决策来源, 批准/拒绝/过期及等待耗时 |
| 回复与交付 | 生成正文, 实际发送正文, 分段和目标, 平台回执, 部分完成或未知结果 |
| 请求终态 | success, failed, timeout, cancelled 或 interrupted, 是否记录完整 |

状态控制字段和动态工具返回内容分离, 不用一个 Any 包含全部事件协议; 业务返回 success=false 与工具执行是否抛异常分别记录

对于未进入内置执行器的自定义 Session, 保留入站/出站链路, 其内部未接入的阶段明确标记不可观测, 不宣称已完整采集

### 6.1 超时和流式中断

模型/工具执行前即记录开始, 成功, 异常, 取消和 finally 收尾位置补充对应终态; 不只在执行成功后追加一条合并事件

区分 session_timeout, network_timeout, operation_timeout 与主动取消, 记录实际配置; 模型 SDK 自动重试保持原设置, 无法观测的 SDK 内部尝试不伪造编号

流式文本按时间或字节阈值合并保存部分输出, 初值 250 ms 或 32 KiB, 不逐 Token 写库; 最终输出引用已有文本块组合, 不把所有块和完整正文再存两遍

进程异常退出后, 开始事件没有匹配结束事件时显示未确认中断; 不因时间过长自动填成工具失败或成功

### 6.2 重试与分支

重试新建请求并关联原请求/回复版本, 恢复执行关联同一业务 run 及新的执行尝试; 不混成一次模型调用

已有 Fork 只增加来源上下文, 来源请求/节点和已有检查点关联; 新分支只追加自己的日志, 不复制来源日志正文

上下文回滚和分支切换不删除曾发生的诊断事实, 记录本次变更及前后关联; 日志节点能浏览不等于它具有恢复/Fork 能力

## 7. 保存什么, 省略什么

### 7.1 默认保留

- 实际模型消息序列, 本轮模型参数, 工具定义与配置版本
- 可见模型输出, 工具请求参数与返回, 审批结果, 生成回复与实际交付结果
- 对象, 上下文, 请求和业务执行关联, 各阶段时间, 耗时, 错误码和原因
- 对排查上下文处理有用的摘要水位, 裁剪/压缩统计, 输入来源和资产资料

### 7.2 默认不保存

- sections 等上下文拼装原材料的完整展开, 保留来源和版本标识即可
- 已有实际 messages 后再分别保存一份 system_prompt, turn_prompt 和完整 dialogue_history
- 每个检查点或候选里的全部历史事件正文副本
- 未改变内容却单独复制的审校后正文
- 图片/视频/文件二进制和 Base64, 重复文件正文, 认证头, API Key 与签名 URL 的敏感参数
- 每个 Token 的独立日志, 无来源依据的推断内容

正文精简是诊断能力取舍, 明确标记省略原因; 不自动删减已有恢复状态, 不把业务依赖的摘要水位和投递标识按 debug 明细清理

首版不额外提供保存完整 sections 的第二个深度档位, 避免重新引入已确认的大量重复记录; 如之后需要, 单独评估其容量与用途

## 8. 存储和查询

### 8.1 独立诊断库

建议按服务使用 .satrap/logs/debug/control.sqlite, backend.sqlite, chat.sqlite, 不写业务 platform.db

| 逻辑表 | 职责 |
| --- | --- |
| debug_objects | 稳定对象身份与展示索引, 不作为设置权威来源 |
| debug_contexts | 对象下的主/子上下文及历史归属 |
| debug_requests | 请求摘要, 上下文, 来源和终态 |
| debug_events | 阶段事件, 父子关联, 有序序号及正文引用 |
| debug_bodies | 按内容摘要共享的消息, 参数, 结果与文本块, 含编码和原始长度 |

静态 system 消息, 历史消息和工具定义等相同正文只存一次; 不通过当前 event_id 查找可变记录代替历史内容

正文使用明确类型和编码版本, zlib level 1 按收益决定压缩; 不采用每节点完整快照, 不建立需要无限回溯的请求引用链

模型输入的有序消息引用也需要共享: 优先复用已有请求编码的共同前缀和增量思路, 对引用深度设置上限并使用有限基础快照; 对长序列比较分块共享方案, 不把越来越长的消息 ID 列表在每个节点完整复制后就认定存储已线性增长

诊断正文池独立保留脱敏后的历史版本, 不能只保存业务数据库的可变行 ID; 业务历史被修改或清理后, 未到期诊断仍能展示当时采集的内容

按对象/上下文/时间, 请求内序号, 请求状态建立所需索引; 不通过扫描全部业务库或全部文本日志获得页面目录

### 8.2 写入和有界缓冲

共用执行事件在请求作用域内传递, 线程池和子 Agent 显式继承; 每服务使用有界后台写入队列和短事务批量追加

采集时固定事件内容及顺序, 后台落盘时不能重新读取可能已经变化的上下文或工具结果; 不在请求线程完整复制和序列化全部历史快照

大正文实行预采集预算, 先限制原始字节量和缓冲占用, 再压缩; 不能先构造无界大字符串再截断

队列满时优先保留开始/结束和错误等有界元数据, 正文明显标记丢失; 无法写入诊断库时限频报告独立运行警告, 不递归写相同故障 logger

事件序号缺口, 正文未落盘, 截断, 超预算或磁盘故障均体现为 incomplete 及具体原因, 不静默冒充完整链路

### 8.3 清理和隔离

按整条已结束请求清理, 先解除事件引用, 再批量回收无引用正文; 处理跨上下文或分支共享正文时保留有效引用

诊断库不作为恢复执行的唯一数据来源, 清理诊断数据不使现有 RunStore 或检查点失效; 业务引用显示可用/已删除/已归档等真实状态

WAL checkpoint 和碎片整理在维护时执行, 不逐请求 VACUUM; 展示逻辑有效字节, 库文件和 WAL 实际占用, 不能用 DELETE 行数冒充磁盘已释放

各服务按独立认证接口提供摘要和详情, Control 聚合目录但不要求 Backend 在线; 关闭的服务显示覆盖缺口, 不伪装成没有记录

相同正文可能被不同对象引用, 详情读取必须经已授权事件关联校验, 不提供仅凭全局内容摘要就能直接取正文的接口

## 9. 前端位置与操作

### 9.1 路由

- 现有 /logs 保留运行日志, 增加高级 Debug 入口
- 新增 /logs/debug, 显示高级 Debug 页面, 深链接携带对象与 context_id
- 两页面采用统一导航, 不把高级功能塞进原有日志行工具栏

日志监控的功能级认证规则覆盖 /logs/debug 子路径, 不能只识别现有精确 /logs 路径; 来源认证和密码恢复按原服务分别处理

### 9.2 页面默认按上下文索引

列表首列为会话上下文标题和 ID, 同时展示所属群/私聊/Chat, 平台账号, Agent, 最近链路时间, 请求数量和异常数量

支持按平台, 对象, 主/子上下文, 时间, 结果和是否开启筛选; 列表与计数分页, 不载入全部上下文或正文

顶部提供整体默认和容量/保留设置入口; 选中上下文后展示其所属对象开关, 明确标注这是群/私聊对象设置, 同对象的所有上下文共用

开启提示示例: 本群高级 Debug 已开启, 对本群现有及以后新上下文生效

同一群的 C1 和 C2 不出现互相矛盾的两个开关; 在 C1 修改对象设置后, C2 的设置标记同步更新

没有日志但存在的上下文仍可从既有目录选择并开启; 通过分页目录关联, 不为开关操作激活或恢复冷 Session

### 9.3 上下文详情

点开上下文后按请求列出链路, 默认时间线显示输入, 模型, 工具, 审批, 交付和终态; 有重试/Fork 来源时可展开分支关系

正文, 工具参数与结果默认折叠, 点开才按需读取; 页面预览前 50000 字符, 完整链路按单请求流式导出, 单次导出预算 64 MB

出现超时在对应节点展示错误码, 配置值和耗时; 链路检索由服务端按索引进行, 不再受运行日志最近 100 行影响, 首版不提供定位到普通日志具体行的深链

未采集, 已省略, 已清理和故障缺失使用不同提示; 不将空正文一概标记为模型没有输出

## 10. 建议 API 与宿主接口

| 接口 | 用途 |
| --- | --- |
| GET/PUT /config/debug-logging | Control 管理整体默认, 保留/容量和对象覆盖, 修改需 expected_revision |
| GET /api/debug/contexts | 各服务返回分页上下文索引及稳定对象关联 |
| GET /api/debug/requests | 按上下文, 对象, 时间与状态分页查询请求 |
| GET /api/debug/request | 精确读取单请求摘要, 用于来源分支及终态刷新 |
| GET /api/debug/events | 按 request_id 与游标查询时间线, 默认不返回大正文 |
| GET /api/debug/body | 通过事件和正文槽位读取有界详情, 不直接暴露全局摘要查找 |
| GET /api/debug/export | 有界筛选并流式导出, 先验证范围权限 |

plugin_host.debug_logging 提供当前可信对象的 status 和 set_mode, 以及经全局管理授权的默认查询/修改入口; 命令和面板共用设置仓储与校验, 不复制一套状态

对象设置存储由宿主持有, 命令插件不负责落盘日志或维护日志数据库

路径为职责划分建议, 实施前按现有目录确认, 不在 core 根目录散放新模块

| --- | --- | --- |

| D: 验收 | 集中回归, 长期增长与性能, 文档 | 扩展现有 logging, pipeline, workflow, display, plugin/command 测试和现有浏览器场景 |

优先复用既有模块和短事务工具, 新增模块只承担具体职责, 不额外建立通用事件总线框架

每批可单独审查; 本计划仅安排实施与本地验证, 提交和服务器部署按后续用户要求执行

## 12. 验收与性能门槛

### 12.1 业务与设置

- 群内 /debug on -> 请求 -> /new -> 新请求, 两个上下文均记录且共用同一对象设置
- /switch, 冷恢复, 后端重启后覆盖仍在; 不同平台实例, 机器人账号, 群和私聊不串设置
- 群共享与按用户隔离上下文均受当前群设置影响, 不随发话人改变
- 全局默认变更仅影响 inherit, 显式 on/off 不变; reset 恢复动态继承
- 请求中途改开关仅影响下次请求, 页面和命令状态来源一致, 并发修改返回冲突
- 未授权用户与模型工具不能修改开关; 禁用命令插件不影响宿主已保存设置
- Backend 未运行仍能打开页面并管理默认和已有对象, Chat/Control 可独立查询和认证

### 12.2 链路完整性

- 覆盖无工具, 多轮/多工具, 工具正常返回业务拒绝, 工具异常, 审批拒绝/过期, 会话/网络超时, 取消及部分交付
- 流式中断保留已采集部分输出; 开始无结束, 序号缺口和正文丢失均可识别
- 并发请求, 子 Agent, SDK 回调和线程池不串 request_id; 自定义 Session 未观测阶段明确说明
- retry, resume 和 Fork 保留各自来源, 不复制整条来源正文, 不因上下文回滚抹去事实
- 正文还原和共享引用逐项验证, 配置版本/摘要水位与工具调用资料保持不变
- 超预算, 队列满, 写库失败和正文清理不影响业务执行, 不将日志成功等同业务成功

### 12.3 新旧性能对照

沿用现有离线样本验证基准体积, 再增加真正运行 Satrap 的开启前后对照, 不以 Astro 样本的内存实验代替生产验收

| 维度 | 对照内容 |
| --- | --- |
| 关闭开销 | 普通日志基线与高级 logger 关闭时的请求 P50/P95, 事件循环延迟 |
| 开启开销 | 相同模型/工具夹具, 输入大小和回合数下的采集 CPU, 队列峰值, 请求及后台写入延迟 |
| 存储增长 | 100, 1000, 10000 个事件及多次分支, 每新增事件和正文的实际字节增长 |
| 读取 | 上下文目录, 请求分页, 单节点详情和完整链路导出, 冷/热读取分开 |
| 内存 | 正文大样本, 流式中断, 并发和导出时的进程峰值, 不只看 tracemalloc |
| 清理 | 跨请求正文共享, 活跃链路保护, 达到容量及 WAL 占用时的维护行为 |

存储验收重点是避免每新增节点都重存全部历史; 请求内必要的引用顺序也应验证增长, 不把正文去重后剩余的平方级引用列表忽略

若界面常规浏览必须还原全部上下文快照才能查询, 视为不通过; 目录和摘要查询必须与正文体积解耦

具体服务性能预算在首批基准后给出, 不在没有真实采集链路数据前承诺固定 2 MB 容量或延迟提升
