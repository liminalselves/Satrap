# 平台工具直接发送与跨容器图片修复

## 最终行为

`group_chat_reply` 在工具调用内校验组件, 请求平台发送, 等待实际回执后返回模型; 不保存回复草稿, 不再返回 `prepared`, 管线不再在工作流结束后调用 `commit`

```text
模型发起工具调用
  -> 校验身份, 权限, 路由和资源
  -> QQ: 转换图片内容并请求 OneBot 实现端
     Misskey: 上传 Drive 并发布到目标对话
  -> 等待平台回执
  -> 将结果写入工具消息
  -> 下一轮模型推理或后续工具
```

| 结果 | 工具返回 | 后续行为 |
| --- | --- | --- |
| 已确认成功 | `ok=true, status=sent, message_ids` | 允许新的显式回复, 不重复补发模型收尾正文 |
| 明确失败且无确认内容 | `ok=false, status=failed, error` | 模型可在现有 Agent 循环中修正, 不重跑整个请求 |
| 部分送达 | `status=partial, message_ids, failed_index` | 禁止本轮原样重发该组件链; 不同的显式后续回复仍可发送 |
| 结果未知 | `status=unknown, message_ids, error` | 保留未确认结果, 阻止同轮继续发送, 不自动重试 |

部分回复的摘要仅保存在本轮宿主, 用于阻止原样重发; 持久执行恢复继续沿用工具的 `manual` 策略, 不新增恢复任务或执行循环

当前请求身份, 主工作流校验, 资源归属与文件租约继续保留; 多次显式调用各自等待回执, 请求被取消或路由变化后禁止后续调用

已发生的发送不会因后续模型失败而回滚。未使用回复工具的普通对话仍发送模型最终文本; 工具明确失败且没有任何送达证据时也允许最终文字说明, 已成功或结果不明时禁止管线重复补发

## QQ 图片字节传输

- 本地图片先通过媒体路径白名单, 在有界工作线程中读取并编码为 `base64://`, 实现端不再依赖 Satrap 容器内的文件路径
- 普通消息, 私聊图片和转发节点共用转换入口与单次预算, HTTP(S) 来源沿用原有方式
- 单次消息的本地/内嵌图片原始字节预算为 32 MiB, 编码后约 42.7 MiB; 群聊工具原有更严格的图片数与大小限制仍生效
- 编码线程最多 2 个, 运行与排队任务合计最多 8 个; 逐项编码, 不增加磁盘中转副本
- 编码取消时等待实际线程退出后再释放资源, 平台发送子任务持有自己的媒体租约
- 编码完成后, 紧邻平台请求复核当前连接, 启用状态和受控图片的群/Agent 路由; 等待期间失效的请求不会发出
- Debug 与平台消息档案保留有界摘要, 不保存整段 Base64; 不新增共享业务目录或媒体 HTTP 服务

## Misskey 回执与副作用

- 纯文本与媒体统一返回 `SendReceipt`, 房间, 私聊和帖子都检查实际消息 ID; 缺少或身份不符的确认归为 unknown
- 回执与档案使用发送前冻结的账号身份; 上传期间更换客户端或账号会阻止发布, 发布完成后的账号变化不会把已确认的旧账号消息误判为 unknown
- 帖子和聊天发布使用 `request_once`, 回执丢失时不通过读取接口的重试装饰器重复发布; 读取接口保留原有重试
- 本地图片继续上传字节到 Drive, 取得文件 ID 后才发布; 上传成功不等于消息发布成功
- 上传异常不再静默变成缺图的文字消息; 同批上传结束后才释放资源, 文件读取使用有界工作线程
- API 错误保留 HTTP 状态, 平台码和脱敏消息; 通过 stage 区分上传与发布

## 错误与诊断

`SendReceipt` 新增有默认值的 `error_code`, `error_message`, `stage`, 旧的状态/ID/失败位置/原因参数顺序保持不变; 分段汇总保留错误资料

工具错误包含稳定 `code`, 脱敏 `message`, `platform_code`, `stage`, `retryable`; 不输出完整平台回包或请求正文。OneBot 只读取 retcode 和原因字段, Misskey 读取 error 对象, 常见凭据文本截断并脱敏

Logger 兼容顶层和群聊工具嵌套的错误结构; 参数错误为黄色, 明确执行故障为红色, unknown 显示结果待确认。恢复成功可显示已完成, 最高问题级别仍保留

text 组件含额外字段时明确提示拆出 quote, 不再误报为正文为空; 旧轮次 asset_id 仍需重新登记

## 验收范围

- 同步/异步真实 Agent 工作流: 工具等待回执, 下一次模型请求收到错误码和原因, 修正后得到 sent, 收尾正文不重复发送
- 新的显式回复可继续执行, 参数/来源/子 Agent/路由/连接校验仍有效, 取消后禁止重发, 已发送消息不被后续模型错误撤销
- OneBot 实际分段队列: 保留确认前缀, 失败位置及平台错误; 本地与转发图片都可仅凭编码内容解码, 预算与编码取消具有判别力
- Misskey 实际本地 HTTP: 房间/私聊/帖子返回统一确认, 上传拒绝与发布拒绝区分, 503/回执丢失仅发起一次发布, 凭据不进入公开错误
- Logger 的嵌套错误分类, 已发送/部分完成/结果待确认标题, 既有浏览器日志场景

本轮验证使用隔离替身和本机 HTTP 服务, 没有向真实 QQ 群或 Misskey 账号发送测试消息; 未部署到服务器, 真实平台验收和跨平台 CI 另行确认
