# 对话记录交互与平台统一审批方案

日期: 2026-10-23

状态: 已实现并本地验收, 已按批次提交; 用户随后授权部署, 结果见验收记录

验收记录: [实现与性能结果](platform-approvals-results-2026-10-23.md)

## 1. 本轮范围

1. 对话记录中, 明确模型上下文的当前状态, 去掉不支持 Chat 展示记录时的无说明禁用按钮
2. 在“平台状态”下建立统一审批中心, 集中群管理动作, 机器人入群邀请动作, 好友动作的人工审批
3. 各业务页保留操作发起, 原始申请查询及历史记录, 人工审批入口统一跳转到审批中心

这里集中的是已经形成动作记录, 等待人工批准的操作

原始好友申请, 机器人入群邀请, 成员入群申请不是同一个审批阶段, 不混成一条待审批操作; 它们继续使用现有业务处理流程, 中心提供返回原业务的链接

本轮不新增自动审批规则, 不改变模型权限, 不迁移原动作表, 不重写动作执行器

## 2. 已确认的现状

### 2.1 对话记录

- `Conversations/index.tsx` 默认选择 `context`, 再点“上下文”不会触发切换
- `supports_history=false` 时, “Chat 展示历史”被禁用, 但页面没有解释禁用原因
- 群记录支持读取模型上下文, 原始平台消息属于“平台消息档案”, 与网页 Chat 独立展示记录不同
- 服务器上目标群的两个记录均能正常读取上下文, 分别返回 26 / 216 条消息, 此次没有发现上下文接口故障

### 2.2 审批入口

| 来源 | 现有入口 | 存储 | 批准 / 驳回接口 |
| --- | --- | --- | --- |
| 群管理动作, 含成员入群申请处理动作 | 单群“审批与记录” | 平台数据库 `group_actions` | `groupApi.decideAction` |
| 邀请机器人进群的处理动作 | 群管理页的入群邀请弹窗 | 同一张 `group_actions`, `handle_group_request` 且 `sub_type=invite` | `accountRequestsApi.decide` |
| 好友申请处理, 删除好友, 主动添加好友 | 好友页“操作记录与审批” | 同一平台数据库 `friend_actions` | `friendApi.decide` |

现有群动作列表要求指定群, 不能靠前端逐群翻页来做平台级审批列表

`FriendStore` 构造和 `GroupActionStore(recover=True)` 有恢复副作用, 新的汇总读取不得反复创建这些对象来查询

## 3. 对话记录页调整

### 3.1 显示规则

- 将“上下文”改为“模型上下文”
- 同时支持上下文和 Chat 展示记录时, 显示正常切换标签, 当前标签有明确选中状态, 正确的可访问性标记和键盘操作
- 仅支持上下文时, 直接显示“模型上下文”分区标题, 不保留看起来能点击的单选按钮
- 不支持 Chat 展示记录时隐藏对应标签, 显示一句说明: “平台聊天原文请在平台消息档案查看”
- 支持 Chat 展示记录但记录数为 0 时, 保留可切换标签并显示空状态, 不把“没有数据”当成“不支持”
- 是否支持以服务端能力字段为准, 不通过平台名称写死判断

### 3.2 内容与跳转

- 保留上下文范围选择器, 在消息区明确显示“共 N 条消息”和正在查看的范围
- 保留实际加载状态, 读取错误和重试按钮, 不让空白区域代替这些状态
- 增加“查看平台消息档案”链接, 首版携带已有平台筛选, 不从编码后的 conversation_id 猜群号
- 保留“版本与恢复”入口和未保存编辑的离开确认
- 若选中的记录变化, 范围和标签状态一起重置, 避免显示上一条记录的数据

不修改全站 Button / Tabs 的通用视觉规则, 将改动限制在这个页面

## 4. 审批中心的页面组织

### 4.1 位置与路由

- “平台状态”增加“平台列表 / 审批中心”导航
- 新增 `/platforms/approvals`, 使用独立懒加载页面, 侧栏仍归在平台状态
- 平台状态页顶部提供“审批中心 · 待审批 N”入口
- 每个平台卡片增加“审批”链接, 进入时带该平台筛选
- 原群 / 好友 / 邀请入口跳转时带平台, 机器人账号, 来源, 群等筛选; 能携带动作 ID 时直接定位动作
- 刷新页面及浏览器前进 / 后退保留筛选, 使用 URL 查询参数保存

### 4.2 默认视图

默认“待人工审批”, 支持切换“执行中 / 全部记录”及其他状态筛选

| 筛选 | 内容 |
| --- | --- |
| 平台 | 全部 / 指定平台实例 |
| 机器人账号 | 当前账号 / 指定历史账号, 历史账号仅查看 |
| 来源 | 全部 / 群管理 / 入群邀请 / 好友管理 |
| 群或用户 | 指定目标, 原入口跳转时自动带入 |
| 状态 | 待人工批准, 准备执行, 执行中, 成功, 失败, 未确认, 已驳回, 已过期 |

`ready` 是好友动作的准备执行状态, 不等同于待人工批准, 不计入待审批徽标

列表展示平台与机器人账号, 来源类别, 目标群 / 用户, 具体操作, 发起来源, 提交时间, 到期时间及结果

优先展示可理解的操作说明, 例如“禁言成员 12 小时”, “解除全员禁言”, “删除好友”, “拒绝某条好友申请”; 原始参数放入可展开详情, 不整页堆 JSON

### 4.3 决策语义

- 操作按钮使用“批准执行 / 驳回操作”
- 明确展示将执行的原动作: 批准一个“拒绝入群邀请”的动作, 不得在文案里变成“接受邀请”
- 沿用原有业务确认规则和审批接口, 不新增一层后端人工审批
- 审批后重新读取动作状态, 根据实际结果显示等待, 执行中, 成功或失败
- `unknown` 不显示重试执行按钮, 不自动重复提交
- 账号已切换, 平台离线, 动作到期或仅有历史记录时禁用决策并给出原因
- 并发处理或网络超时后先读取原动作, 不生成一个新动作 ID 重发
- 首版只提供单条审批, 不增加批量批准

## 5. 后端读取与接口

### 5.1 新增汇总读取

建议新增 `satrap/core/platform/action_catalog.py`, 只负责动作目录查询与统一响应, 不成为第二套执行器

新增 Backend API:

- `GET /api/platform-actions`: 平台 / 账号 / 来源 / 状态 / 目标筛选, 有界分页, 返回统一列表和覆盖情况
- `GET /api/platform-actions/summary`: 平台状态页的待审批计数, 只读计数, 不返回全部动作正文

人工决策继续使用已有三类业务接口, 不新增统一写入接口

前端新增带明确来源类型的 `platformActions.ts`, 根据 `source` 分派给原有 `decideAction` / `decide`, 不根据 action_id 前缀猜来源

### 5.2 读取口径

- 每个平台只查询该平台数据库, 将 `group_actions` 与 `friend_actions` 的公共列归一化后筛选分页
- 同一条 group_actions 邀请记录只归入“入群邀请”, 不再重复出现在“群管理”
- 列表主键包含平台, 机器人账号, 来源和原 action_id, 防止不同平台或表中的 ID 碰撞
- 使用原有公开记录序列化和必要字段白名单, 不向前端暴露处理 flag, 私有模型来源凭据等内容
- 到期口径统一, 使用同次查询时间将已经过期的 pending 显示为 expired; 新汇总读取不为修正计数写入原表
- 查询已有数据库使用只读连接; 不创建空平台数据库, 不触发 schema 迁移或进程恢复
- 一个平台的一页和计数使用同一只读快照; 跨平台汇总不宣称是全局原子快照
- 多平台读取并发上限为 4, 不逐群请求成员列表或平台网络接口
- 默认每页 50, 最大 100; 使用时间和完整身份组成稳定游标, 筛选变化后清空游标
- 单个平台查询失败时保留其他平台结果并明确列出缺失范围; 不把读取失败显示成“待审批 0 条”
- 后端未运行时明确显示暂不可读取 / 审批, 不新增 Control 侧的旁路执行能力

### 5.3 权限和执行

- 平台和当前机器人身份仍由后端核验, 列表参数不是授权依据
- 新入口复用原审批方法中的权限复核, 账号代次检查, 群状态检查, 保护名单, 请求修订和原子占用
- 不能因为在审批中心中可见, 就保证该动作仍可执行; 最终以原决策接口的复核结果为准
- 此轮不统一或搬迁各类审批策略设置, 平台默认策略和单群覆盖继续保留原继承关系

## 6. 原入口收拢与刷新

- 群“审批与记录”改成“动作记录”, 保留按群的历史视图, 将人工批准按钮改成“前往审批中心”
- 好友“操作记录与审批”改成“操作记录”, 同样跳转统一中心处理待审批动作
- 邀请弹窗保留原邀请的接受 / 拒绝业务处理, 待审批动作区域使用统一跳转, 不保留第二套批准按钮
- 提交一个返回 pending 的业务操作后, 给出“已提交, 前往审批中心”的明确入口
- 原路由及书签可继续进入相应记录页, 不删除原后端业务接口
- 待审批页在前台每 10 秒刷新, 隐藏页面停止; 执行中状态可沿用现有短时 2 秒刷新, 最长 60 秒后回到普通刷新
- 平台列表只轮询摘要, 不预加载全部动作; 其他页面不新增全局审批轮询
- 请求取消和账号切换使用当前范围校验, 旧请求不得覆盖新筛选结果
