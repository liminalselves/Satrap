# 插件聊天命令计划与契约

日期: 2026-10-06

状态: 计划已记录, 尚未实施

后续进展: 宿主权限声明与同步 / 异步原生命令绑定接口已在 [统一权限契约](plugin-management-permission-contracts.md) 中实现. 本文的业务查询与审批新命令仍待后续实施, 不能将已有宿主接缝当作这些命令已经上线

范围: 本次 PR 新增的 group_chat, friend_manager 和 memory 插件, 以及本轮扩展的既有 group_admin 插件. 本轮不修改 satrap_coding 权限机制, 不提交或重启服务

## 1. 当前缺口

| 插件 | 当前命令 | 缺口 |
| --- | --- | --- |
| memory | /memory; 群内支持列表, 添加本人偏好和删除 | 详情, 修改, 群记忆提案, 待审批列表及审批; 群内结果直接返回 JSON |
| group_chat | 无 | 提醒管理, 已保存摘要查询, 表情查询与按群设置 |
| group_admin | 无 | 群管理申请列表, 详情, 批准, 拒绝及结果查询 |
| friend_manager | 无 | 好友查询, 好友申请处理及删除好友申请审批 |

现有 /approve 属于 satrap_coding, 仅管理编程权限策略及规则, 不用于以上业务申请

## 3. 命令注册与身份契约

1. 插件仍独立提供 commands 工厂并在 meta.yaml 声明能力; 新命令适配同步和异步会话, 尊重插件及命令启停
2. 为命令及子命令声明权限元数据, 支持普通查询, 本人操作, 指定范围管理和审批等不同要求; 不继续把新命令名加入平台层硬编码名单
3. 路由到会话并确认实际命令注册后, 在执行前统一检查权限; 兼容现有命令工厂, 命令冲突继续拒绝安装
4. 身份只来自本轮原始平台消息的 CallOrigin; 不接受命令参数填写 actor, operator, self_id 或平台实例来冒充身份
5. 群聊沿用显式 @机器人 的命令寻址, 私聊不要求 @; 不把引用, 转发, 工具结果或模型输出解析为人工批准
6. 宿主解析当前平台, 机器人账号, 对话与操作者权限; 审批者通过配置明确授权, 平台角色与 Satrap 操作权限不默认等同
7. 平台能力通过适配器接口判定; 不写死 QQ, OneBot 角色值或数字 ID 规则
8. 权限不能保存在共享 Agent 会话或继承给子 Agent; 等待后和执行前重新核验身份, 配置, 连接与目标归属

## 4. 模型与人工命令的权限契约

以下为设计方向, 具体开关和权限粒度须依据权限核查结果确定

- 插件启用, tools 勾选, handlers 勾选, commands 勾选分别控制不同入口
- 模型写操作开关和调用者名单不自动授予人工命令管理权; 人工命令通过独立命令授权进入同一宿主服务
- 人工命令审批不能绕过宿主禁止策略, 账号保护名单, 对话范围, 平台能力或原申请来源校验
- 关闭模型工具不应自动关闭已经独立授权的人工审批命令; 插件整体关闭时, 插件命令停止提供, 后台管理入口仍按原认证机制工作
- 审批命令可以继续查看或拒绝已有申请, 但批准执行仍须原模型授权有效; 提醒创建与恢复还必须保留当前后台发送开关和范围检查
- 普通成员仅管理本人记录; 群记忆, 群管理申请和他人提醒由明确授权的管理者操作
- 首批不开放通过聊天命令修改安全名单, 模型写开关, 审批默认策略或批量清空

## 5. 审批与执行契约

1. 命令与前端复用记忆提案, 群动作和好友动作的现有状态机, 不创建第二套审批数据库
2. 批准指定的完整申请 ID, 展示动作, 目标, 内容, 发起者, 期限及当前状态; 不支持隐式批准最近一条或批准全部
3. 审批使用读取时的版本或指纹; 内容变化, 权限变化, 来源失效或过期时拒绝, 提示重新查看
4. 同一申请重复批准或并发批准不重复执行; 重启后已失效的申请不得由命令重新激活
5. 用户确认操作直接由宿主处理, 不调用模型判断批准意图, 不新增可供模型调用的审批工具
6. 记录实际审批者, 审批来源 command 或 panel, 平台, 账号, 群及来源消息; 不把平台命令统一记成 authenticated_operator
7. 仅批准申请不等同平台执行成功; 分别返回 pending, approved, succeeded, failed, unknown 等实际状态
8. 命令失败经过统一日志和异常边界, 返回可读错误, 不中断平台进程

## 6. 实施批次

| 批次 | 内容 | 验收 |
| --- | --- | --- |
| P1 | 命令权限元数据, 可信命令调用者, 子命令解析及帮助 | 普通查询可用, 未授权审批拒绝, 引用或模型输出不执行, 平台能力不写死 |
| P2 | 群记忆, 群管理及好友删除申请的查询与审批命令 | 范围隔离, 实际审批者审计, 过期或版本冲突拒绝, 并发不重复执行, 前端与命令结果一致 |
| P3 | 记忆个人操作, 群记忆提案, 好友查询与申请处理, 提醒创建和恢复 | 所有权, 开关与命令授权分离, 明确目标, 禁止绕过保护名单, 提醒不重复发送 |
| P4 | 摘要查询或删除, 表情查询或按群启停, 文档和人机交互完善 | 来源失效正确展示, 删除不影响原文, 配置冲突保留草稿, 停用生效 |

每批形成独立可审阅更改和对应验证, 经后续实施授权后分批提交

## 7. 权限核查结果

已逐项核对本次 PR 的新增插件与本轮扩展的 group_admin 能力, 覆盖:

- 模型工具, 前处理和记忆注入
- 人工命令与现有前端入口
- 名单的空值语义, 开关默认值与审批是否强制
- 自身操作, 本人记录, 群管理, 跨群和账号级操作的范围
- 启用工具是否同时具备读取或写入能力, 实际执行是否再次检查
- 配置名称与实际行为不一致, 入口之间可绕过权限或授权粒度不足的情况

核查结果已保存为 [新增插件权限核查](plugin-permission-audit.md), 包含默认值, 名单空值语义, 实际执行校验和命令所需的独立授权. 实施时依据该清单细化契约, 不自动改变现有权限默认值

系统管理员的统一身份目录与按管理组划定的插件授权范围, 采用 [系统管理员与插件授权计划](system-administrator-plan-contracts.md). 模型名单和人工命令均可查询该宿主身份服务, 各入口继续独立校验其功能开关, 操作范围和审批要求

管理命令的声明与统一授权 API 采用 [插件管理条目声明与统一授权契约](plugin-management-permission-contracts.md), 子命令精确匹配并沿用同一宿主校验
