# 前端信息加载与记住登录改进计划

日期: 2026-10-23

状态: 已获准实施, 功能与回归已完成, 最终实测和边界见 `frontend-loading-and-login-results-2026-10-23.md`

## 1. 目标与范围

- 降低仪表盘, 模型与插件配置, Chat 和对话记录页面的信息加载延迟
- 修复已有 Cookie 无法恢复登录的问题, 支持同一浏览器下次访问免输密码, 包括服务和浏览器重启后的恢复
- 实施前建立新基线, 实施后使用同一套 benchmark, 同一数据与环境进行对比
- 保持现有权限, 配置一致性, 历史切换, 回答变体和工具记录的语义
- 生产数据和远端部署不参与基准写入, 本轮不处理动画风格, 网络搜索和模型推理性能

## 2. 已确认的问题

| 问题 | 当前行为 | 主要位置 |
| --- | --- | --- |
| 配置请求瀑布 | 单个冷读取依次查版本, 读正文, 再查版本; 仪表盘五类资源共 15 次配置请求 | `satrap-ui/src/api/configVersions.ts`, `src/hooks/useConfigWatch.ts` |
| Chat 全量会话读取重复工作 | `list_conversations` 循环读取每页 200 条, 但每页重新聚合全部轮次并在 Python 中排序切片 | `satrap/display/recorder.py` |
| 同步查询阻塞 | Chat 会话和历史查询直接在异步路由内执行 | `satrap/display/server.py` |
| 长历史全量加载 | 一次读取全部轮次, 回答变体和工具记录, 前端创建全部消息组件 | `recorder.py`, `satrap-ui/src/pages/Chat/index.tsx` |
| 管理目录先全量后分页 | 逐个平台读取全部目录, 再筛选和分页, 指定 ID 也没有独立快路径 | `satrap/core/backend/control_server.py`, `core/config/conversation_catalog.py` |
| Chat 初始化等待与重复请求 | 健康检查后整批等待插件, 项目, 会话和模型; 公共模型加载后又读一次 Chat 模型详情 | `satrap-ui/src/pages/Chat/index.tsx` |
| 已有 Cookie 无法恢复 | `/auth/session` 只接受 Bearer 或允许的回环 bootstrap, 不接受已有 Cookie 恢复; 前端每次启动都会调用该接口 | `satrap/core/server_auth.py`, `core/utils/minihttp.py`, `core/backend/control_server.py` |
| 登录状态不能跨服务重启保留 | Cookie 当前有 Max-Age, 但有效期仅 8 小时, 服务端会话仅保存在进程内 | `satrap/core/server_auth.py` |

排查阶段的隔离复现结果仅用于确定方向, 不替代正式基线:

- 仪表盘冷启动 20 次 API 请求, 其中 15 次配置请求
- Chat 冷启动 14 次 API 请求, 模型详情读取两次
- 每次 API 模拟增加 150ms / 300ms 等待时, 仪表盘配置阶段约 0.5s / 0.93s
- 使用当前生产查询函数和内存 SQLite, 每会话 10 轮, 读取 1,000 / 5,000 个会话的中位耗时约 36ms / 821ms
- 上述浏览器模拟不包含真实网络握手, TLS, 磁盘和服务器负载

## 3. 批次 A: 先建立可重复的 benchmark

### 3.1 基线规则

1. 先固定开始实施时的 Git 提交, Node / Python / Chromium 版本, 构建参数和数据种子
2. 先补充基准夹具和指标, 在生产修改前运行 baseline
3. 最终 after 使用相同基准代码, 数据和机器; 中途基准修正时, baseline 与 after 一起重跑
4. 前端使用生产构建, 排除 Vite 开发模式和 StrictMode 开发期重复 Effect 的影响
5. 分开测量冷缓存与热缓存, 首次密码登录与已有 Cookie 恢复, 不混算平均值
6. 每场景 2 次预热, 10 次正式运行, 报告 P50, P95 和样本数; 后端查询微基准采用 30 次正式运行
7. 最终报告显示实际数值和回退项, 不只写通过; 环境或数据不同的结果不计算改善比例

### 3.2 测量层次

| 层次 | 方法 | 回答的问题 |
| --- | --- | --- |
| 浏览器隔离基准 | Playwright + 当前生产构建 + 固定 HTTP / WS 夹具 | 请求轮次, 前端等待, JS 解析与渲染占比 |
| 后端查询基准 | 独立临时 SQLite 数据库 + 实际查询函数 | SQL, 聚合, 排序和分页成本 |
| 本地端到端 | 隔离的 Control / Backend / Chat + 合成数据 + 真实 Cookie | 认证, 查询, 序列化, 传输和页面显示的合计成本 |
| 远端抽样 | 经用户授权后仅执行读操作, 记录接口时延 | 部署环境下是否取得同方向改善; 不与本机基线直接比较 |

### 3.3 场景与指标

| 场景 | 数据与条件 | 必须记录的指标 |
| --- | --- | --- |
| 仪表盘, 模型, 插件页面 | 冷 / 热缓存, 每次 API 额外等待 0 / 150 / 300ms | 导航至主要数据可见, 总 API 数, 版本请求数, 串行层数, 响应字节数 |
| Chat 初始化 | 首次登录 / 已记住登录, 一个非当前必需服务离线 | 密码门解除, 会话列表, 模型列表各自可见时间; 重复请求和失败状态 |
| Chat 会话列表 | 100 / 1,000 / 5,000 个会话, 每会话 10 轮 | 首屏查询时间, 完整遍历时间, SQL 执行次数, 返回字节数, 服务端内存 |
| 长对话打开与向前翻页 | 100 / 1,000 / 5,000 轮, 包含工具与多个回答变体 | 首批历史可交互时间, 单页加载时间, JSON 字节数, DOM 节点, JS Heap, Long Task |
| 对话记录列表与详情 | 单平台 / 多平台, 含旧路由格式和独立工作流上下文 | 首屏, 翻页, 精确 ID 查询耗时, 扫描记录数, 分类及总数正确性 |
| 查询期间的其他请求 | 长列表读取时并发健康检查和 WS 心跳 | 健康检查 P95, 事件循环延迟, WS 延迟 |
| Cookie 恢复 | 浏览器重开, 单服务及全部服务重启 | 恢复耗时, 密码提交次数, Cookie 签发次数, 持久存储读写次数 |
| 现有交互基准 | 复用现有滚动, 流式增量和主题场景 | FPS, Long Task, 内存, 消息与流式结果完整性 |

时钟口径:

- 页面计时从导航开始, 以对应数据实际出现在 DOM 并可操作为结束, 不以 HTTP 200 或 loading 消失替代
- 分别记录 UI 配置发现, 会话恢复, 请求排队, 服务端处理与前端提交时间
- 网络等待由夹具或受控代理统一施加, 记录为模拟条件, 不称为真实公网 RTT
- 历史 benchmark 的滚动测量仍在加载完成后开始, 新增加载测量覆盖此前未统计的初始化过程

## 4. 批次 B: 修复配置读取链路

### 4.1 仪表盘只读摘要

- 增加轻量配置概览读取, 返回模型分类数量和会话类数量, 不为统计数字下载完整配置
- 仪表盘配置读取目标为一次请求, 状态读取仍由现有状态链路负责
- 配置概览包含来源版本, 后续刷新按版本更新, 保留配置错误的明确状态

### 4.2 共享读取协议

- 对现有配置读取增加显式选择的版本信封, 内容与对应版本来自同一次一致性读取
- 现有接口默认响应格式保持兼容, 新客户端选择版本信封; 版本来自实际读取的来源快照
- 冷读取由一次内容请求完成, 不再强制前后各发一次版本请求
- 热缓存复用按服务和资源合并的版本探测, 未变化时保留原对象引用, 变化时只读取受影响的内容
- 同时发出的相同版本探测共享在途请求; 取消单个订阅者不影响仍在使用的请求
- 多来源资源在服务端使用现有来源快照和有界复核, 不为了减少请求而把版本与正文错配
- 保存仍使用原有 revision 冲突检查, 读取优化不改变写入并发语义

### 4.3 初始化显示

- Chat 的会话, 项目, 插件和模型分别提交加载结果, 一个接口慢不再挡住其他信息显示
- 合并初始化与模型变更触发的模型详情读取, 同一来源版本只触发一次有效读取
- 认证错误, 服务未启动和业务数据为空保持区分
- 密码门按页面实际需要的服务处理认证, 非当前页面必需服务的离线状态不挡住已认证页面
- 受保护数据必须在对应服务授权后加载, 不以先显示数据来缩短密码门计时

## 5. 批次 C: Chat 会话与长历史按需读取

### 5.1 会话目录

- 消除 `list_conversations` 通过分页函数反复构造全量目录的实现, 原有全量接口也只做一次全量工作
- 增加明确的分页读取入口供 UI 使用, 默认先取最近 50 个会话
- 筛选, 稳定排序和分页尽量在 SQL 内完成; 使用活动时间与会话 ID 组成游标, 不只按时间排序
- 已显示数据按会话 ID 合并, 后续翻页不丢失或重复; 同时有新会话时保留稳定分页边界
- 项目筛选和搜索由服务端查询, 不将尚未加载的会话误报为不存在
- 首轮不引入持久化统计表; 先以实际 benchmark 判断单次聚合和索引是否已足够

### 5.2 对话内容

- 增加历史分页入口, 首次读取最近 50 轮, 返回顺序仍为从旧到新
- 向上滚动时按轮次与记录 ID 的稳定游标加载更早历史, 保持滚动锚点
- 首屏返回当前回答变体, 变体数量及必要工具信息; 用户切换时再读取对应变体详情
- 原有全量读取入口保留原语义, 不对旧调用者静默截断
- 消息 ID, 工具顺序, 附件, 文件下载, retry / fork, 运行恢复和变体切换纳入整体验证
- 翻页期间收到流式增量或切换会话时, 旧响应不得覆盖当前消息
- 不在首轮直接引入完整虚拟列表框架; 分页后仍未达到 DOM / 渲染目标, 再实施窗口渲染

### 5.3 查询执行位置

- SQLite 查询和必要的重序列化移到有界工作线程, 不直接阻塞 Chat 事件循环
- 连接在线程内创建和关闭, 已有活跃 recorder 的读取遵守其锁与快照边界
- 并发查询有上限, 超时和取消不遗留连接或无限排队
- 大历史请求期间同时测量健康检查和 WS, 验证改善没有转化为线程池拥堵

## 6. 批次 D: 管理面板对话目录

- 为精确对话 ID 和所属平台增加直接定位路径, 不为一条详情重建全部平台目录
- 列表读取将可表达的过滤, 计数, 排序与分页下推到 SQL, 避免先读取所有正文与轮次
- 分类标签与 facets 分开设计: 总数和筛选项仍对应完整查询范围, 不能用当前一页冒充完整结果
- 多平台查询使用有界并发并保留各平台错误, 不再无条件逐个平台串行等待
- 旧上下文归属和特殊工作流仍按原规则归类, 无法走快路径时保留明确的兼容读取路径
- 不使用无失效依据的长期缓存遮盖问题, 不用提前截断数据换取性能

## 7. 批次 E: 同一浏览器记住登录

### 7.1 用户可见行为

- 登录页增加默认勾选的 `记住此浏览器 (30 天)`
- 勾选后, 关闭并重开浏览器, 刷新页面或重启 Satrap 服务, 下次访问可恢复登录
- 默认有效期为 30 天, 有效登录恢复时按需续期, 同一天不反复续写; 连续 30 天未访问后重新输入密码
- 取消勾选时保留当前短会话策略, 不创建持久登录记录
- 增加 `退出登录` 入口, 退出当前浏览器在本部署各服务的登录, 失败的服务明确显示未完成
- 修改或重置访问密码后, 旧的密码登录凭据失效, 包含未重启的其他服务
- 此设备具体指同一浏览器配置, 不使用设备指纹; 无痕模式, 清除 Cookie 或换浏览器需要重新登录

### 7.2 复用现有 Cookie, 补齐恢复与持久化

1. `/auth/session` 先校验已有有效 Cookie, 有效时直接恢复, 不再返回需要密码
2. 使用现有按服务命名的 Cookie 承载随机凭据, 不另建功能重叠的 Cookie
3. 只有密码登录显式选择记住时才签发持久凭据, Bearer 和原有短会话的默认行为不自动升级
4. 使用 credentials 目录中的专用 SQLite 存储持久会话, 与平台业务数据库分离, Docker 通过已有 credentials 持久卷保留
5. 记录仅包含随机令牌的摘要, 服务命名空间, 部署范围, 密码版本, 创建时间, 续期时间和过期时间, 不保存明文密码或主 API Token
6. 持久会话使用真实 UTC 到期时间; 原有进程内短会话可以继续使用单调时钟
7. 三个服务复用存储实现并按命名空间隔离, 一次界面输入完成各实际可用服务的登录
8. 恢复现有持久 Cookie 不得调用原有短会话签发覆盖它, 避免刷新页面后从 30 天退回 8 小时
9. 验证走有索引的单条读取, 登录, 续期, 退出和清理才写入; 认证 I/O 不直接阻塞事件循环
10. 定期有界清理过期记录, 容量有限; 不在每次 API 请求执行整表清理或更新 last_used

服务启动时间不同的补充: 同主机, 同部署 Token, 同密码版本的其它管理服务持久 Cookie, 可以在 `/auth/session` 中经过核验后换取本服务 Cookie; 普通 API 仍只接受本服务 Cookie, 不支持跨域名继承. 退出时撤销当前请求携带的同部署管理凭据, 避免离线服务残留凭据重新恢复登录

### 7.3 失效与浏览器兼容边界

- 密码版本与部署凭据范围不匹配时拒绝持久 Cookie, 包含跨进程修改密码及部署 Token 变更
- 密码版本探测复用配置来源快照, 避免每个 API 重复解析整个 YAML; 配置修改后及时失效, 不能通过重启才能生效
- 退出撤销服务端记录并清理 Cookie; 退出后复制旧 Cookie 不能恢复
- Cookie 保留 HttpOnly, SameSite 和 host-only 范围, HTTPS 时设置 Secure
- 保留当前允许的同站不同端口访问; HTTPS 反向代理只从可信部署信息判断外部协议, 不盲信外部 Forwarded 头
- 不为本功能扩大 CORS 白名单或自动改成跨站 Cookie; 不承诺跨域名同步登录
- 登录失败不写持久记录, 错误 Cookie 不清空其他服务的有效状态
- 存储不可写时明确报告记住失败, 不能提示已记住却只创建进程内状态; 损坏记录不降级为放行

## 8. 前后 benchmark 验收目标

以下是实施目标, 不是预先声明的结果; 完成后报告实测是否达到

| 项目 | 验收目标 |
| --- | --- |
| 仪表盘冷读取配置 | 配置读取从 15 次降为 1 次摘要请求, 不下载完整模型配置 |
| 配置冷读取 | 内容与版本单次往返取得, 热缓存共享版本探测, 保持缓存失效正确 |
| Chat 模型初始化 | 同一来源版本的有效详情请求从两次降为一次 |
| 延迟网络下的数据可见时间 | 150ms / 300ms 模拟等待场景主要页面 P50 至少改善 30%, P95 不回退 |
| 5,000 会话首屏 | 不再循环读取全部分页, 后端 P50 相比正式基线至少改善 70% |
| 长历史首屏 | 默认轮次不超过 50, 传输和 DOM 数量不随总轮次线性增长, 5,000 轮首屏 P50 至少改善 50% |
| 其他请求响应 | 大查询期间健康检查和 WS 延迟显著下降, 不出现随完整查询耗时持续的事件循环阻塞 |
| 登录恢复 | 浏览器与服务重启后零次密码提交, 不因恢复重复执行密码哈希校验 |
| 持久认证开销 | 单独记录持久 Cookie 验证 P50 / P95 和数据库读写数; 热路径不逐请求写入, 不使页面端到端 P95 回退超过 10% |
| 现有交互 | 消息和流式内容完全一致, 滚动及流式基准的主要耗时与内存不得回退超过 10% |

若达不到目标, 报告具体残余瓶颈, 不通过换数据, 删场景或覆盖 baseline 取得通过

## 9. 回归验证与交付顺序

以大流程集成场景为主, 不为每个辅助函数新增零碎测试

1. A: 基准与 baseline, 附原始样本和环境
2. E: Cookie 恢复, 持久会话, 登录 / 退出 / 改密的三服务集成场景
3. B: 配置读取和初始化, 验证跨页同步, 外部修改, 来源变化, 取消与冲突处理
4. C: Chat 会话与历史分页, 验证实时消息, 工具, 附件, 变体, 恢复和分叉
5. D: 管理目录优化, 验证多平台, 用户视图, 旧归属, 总数与分类
6. 完整 after 和 comparison, 保留性能回退及未验收说明

每批独立提交, 功能测试通过后运行对应 benchmark, 最后统一复测
