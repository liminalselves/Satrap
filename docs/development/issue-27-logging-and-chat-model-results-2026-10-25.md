## A. 错误分类与失败反馈

- 模型 SDK 的同步/异步, 流式/非流式入口共用脱敏错误分类, 保留 HTTP 状态, 合法供应商错误码和可用请求标识
- 请求失败通过 error_info 传递, 工作流拒绝把失败当作正常回答提交; 流式 error 会立即结束本轮, 已展示片段仍可保存
- Chat 将失败摘要保存为回复版本元数据, 历史读取与 Fork 均保留; 平台反馈使用相同展示文本
- 会话限时使用 WARNING 和 session_timeout, 模型网络超时使用 network_timeout; 无法确定来自网络的内部 TimeoutError 使用 operation_timeout, 不冒充会话限时
- SDK 自动重试策略和现有 return_false 显式配置保持不变, 没有新增实例级 last_error

## C. Chat 默认模型, 会话绑定与版本资料

- 新增 ChatSettingsStore, 使用 .satrap/config/chat_settings.json, 复用配置修订, FileLock 和原子写入; 缺少文件时沿用 default 名称, 不选择列表第一项
- 整体默认只在创建新草稿/会话时解析; 已有预加载会话保留原绑定, 会话元数据仍使用 conversation_meta.model
- GET/PUT /api/chat/settings 保存整体默认, GET/PUT /api/chat/model 读取与切换会话绑定; 后者与生成和已有会话操作互斥
- 切换先准备客户端与上下文策略, 保存失败恢复旧客户端和策略; 生成中拒绝切换, 不延迟成下一轮隐式修改
- 冷会话为重选而构建的运行时, 只有持久化绑定成功后才加入公共运行时表并通知订阅者; 暂停加载的并发查询测试确认提交前仍读取旧绑定
- 已删除模型可读取原绑定并显式重选, 不用空配置或首个模型回退; 冷会话重选不丢失历史
- send/retry 携带 expected_model, 发现其它标签已改绑时拒绝本次执行并回填绑定; WS snapshot/model_changed 同步当前选择
- 目录只用于初次初始化模型, 迟到的目录结果不能覆盖已确认绑定; 活动会话读取按代次忽略过期响应
- 回复版本保存实际客户端的配置名和模型标识, 旧版本不跟随当前选择修改; 已完成任务恢复仅回放旧结果时沿用旧版本资料, 不冒充新模型生成
- 重试媒体检查发生在新变体创建与上下文回退之前, 能力不匹配不会留下空版本
- 同名配置更新仍采用已有的生成中延后应用; 补齐 Chat 新增/更新模型接口遗漏的 network_timeout 字段
- 前端新增整体默认入口, 当前模型保存等待期间阻止发送/重试; 切换失败明确提示, 不改为其它模型
- Toast 容器移到应用公共层, 避免独立 Chat 页面捕获保存失败却没有可见提示; 流式错误同时追加展示段, 避免部分输出遮住错误说明
