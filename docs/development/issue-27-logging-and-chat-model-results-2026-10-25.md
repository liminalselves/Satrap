## A. 错误分类与失败反馈

- 模型 SDK 的同步/异步, 流式/非流式入口共用脱敏错误分类, 保留 HTTP 状态, 合法供应商错误码和可用请求标识
- 请求失败通过 error_info 传递, 工作流拒绝把失败当作正常回答提交; 流式 error 会立即结束本轮, 已展示片段仍可保存
- Chat 将失败摘要保存为回复版本元数据, 历史读取与 Fork 均保留; 平台反馈使用相同展示文本
- 会话限时使用 WARNING 和 session_timeout, 模型网络超时使用 network_timeout; 无法确定来自网络的内部 TimeoutError 使用 operation_timeout, 不冒充会话限时
- SDK 自动重试策略和现有 return_false 显式配置保持不变, 没有新增实例级 last_error

## B. 已实施与验收

- 文件名按服务和宿主日期合并, 重启追加; 服务写锁覆盖单条多行记录, 复用句柄避免逐条打开锁文件
- 活动租约仍按进程持有; 两个真实子进程共写一个文件, 杀掉其中一个后另一个仍保护共享文件, 最后退出后才允许过期清理
- 清理同时识别新文件名, 旧实例名和最早日期名, 不重命名历史文件
- 三服务复用鉴权后的 GET /api/logs, 增量序号和运行流标识, 5000 条内存缓冲, 单条 16 KiB 和响应正文 256 KiB 上限; 旧 Backend WebSocket 保留
- 日志页独立查询各来源, Backend 离线不阻止 Control/Chat; 各服务密码恢复独立, 游标过期或重启会说明有限快照可能缺失中间日志
- 正常每来源每秒一次, 离线 5 秒退避, 追赶每 250 ms 最多 500 条, 同一来源不重叠; 页面隐藏不发查询, 恢复后补查
- 补齐 Control API 路径分类, 避免日志端点被静态页面回退截获; 没有认证依赖的日志页不被全局密码门遮挡
- 虚拟列表只因用户滚动改变跟随状态, 避免连续批次和行高测量意外关闭自动滚动; 来源内顺序不因时钟回拨而颠倒
