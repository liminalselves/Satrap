# 对象级高级 Debug Logger 实施与验收

日期: 2026-10-26

分支: issue-27; 本地修改, 尚未提交或部署

## 已落地行为

- 日志监控的 `/logs/debug` 独立页面: 按上下文选择, 再查看请求和执行时间线, 支持平台/对象/主子上下文/时间/结果/当前开关过滤和分页
- 默认关闭; 保留 7 天, 总存储目标 512 MB, 单份正文原始预算 8 MB, 单请求正文原始预算 32 MB
- 开关存入 `.satrap/config/debug_logging.json`, 使用配置修订检查和原子保存; 按平台实例, 机器人账号, 群/私聊类型及目标 ID 绑定, 与发话人和上下文 ID 分开
- `/debug on|off|reset|status`, `/debug default on|off|status` 原生命令; 群内开启后, `/new` 和之后恢复上下文沿用对象覆盖, 请求中途修改只影响下一请求
- 群内管理授权只允许管理当前群; 修改整体默认需要全局管理身份; 命令插件不提供模型工具或服务入口
- 新建内置 Edictum 配置和未显式配置的 Chat 默认带入命令插件; 已有显式插件列表及显式禁用保持原值, 需要管理员按需启用 `debug_logger`
- Control 管理设置及冷上下文目录; Backend/Chat/Control 各自提供已认证诊断查询, 不要求三个服务同时在线
- 独立 SQLite 库位于 `.satrap/logs/debug/{backend,chat,control}.sqlite`; 不将诊断正文加入业务数据库, 不更改 RunStore/DisplayRecorder 的恢复协议

## 真实采集边界

平台入口记录真实来源及排队, 前处理和唤醒判定, 投影后的实际文本/媒体引用, 路由上下文, 会话返回和平台交付回执

内置会话记录实际工作流/上下文准备, 最终 SDK 请求参数与响应, 流式部分输出, 工具参数/结果, 执行审批和实际结果; 超时, 取消和异常保留可确认的终态

流式输出按 250 ms 或 32 KiB 合并, 相同候选和工具槽拼接字段, 包含 SDK 实际返回的公开思考字段; 不保存每个 Token 的到达边界, 也不在结束时重复保存完整流式正文

Chat 保留当前请求与已有重试/恢复/Fork 来源关系, 用户切换回复版本记录独立事实; 发送到 WS 队列只记 `queued`, 不冒充客户端已接收

群/好友动作在真实状态事务提交后采集公开结果, 后续审批可沿动作 ID 与数据库/账号命名空间关联原请求; 没有既有来源证据时不推测来源群, 不记录平台处理凭据

自定义 Session 只承诺宿主边界观测, 明示 `custom_partial`; SDK 内部自动重试和平台内部未公开的状态不伪造成独立步骤

## 存储与故障行为

- 冻结后的正文用 SHA-256 标识并以 zlib level 1 轻压缩; 相同实际消息共享, 消息序列使用固定块与稳定二叉目录共享前缀
- 事件索引独立于正文; 目录与分页不读取/还原大正文, 展开槽位时才校验归属及还原
- 后台 FIFO 批量写入, 普通事件 512 个槽位, 首尾帧额外保留 64 个入队槽位; 保留顺序, 不让结束帧越过未写完的中间帧
- 待写正文原始预算 64 MB; 队列/容量/采集预算耗尽和写入失败不阻断业务, 用缺口或 `incomplete` 明示, 状态接口显示丢弃计数和故障
- 正文解码另受 64 MB 唯一节点与展开预算约束, 防止压缩引用无限展开; 原始字符预算与 JSON 编码字节不同, 默认 8 MB 正文中的转义字符已验证可正常读取
- 管理员将采集预算设得很大, 不会取消解码/待写限制; 超出限制的正文可能省略或拒绝展开, 不承诺无限正文
- 定时清理到期和超目标的已结束请求, 回收失去引用的正文, 保护仍活跃请求; 服务重启时已有诊断库恢复清理, 默认关闭且没有库时不创建空库
- 容量是有效页的软目标, 不是物理文件硬上限; 额外显示数据库/WAL 实占, 使用渐进回收和被动 checkpoint, 不频繁整库 VACUUM
- 写入器使用独立 OS 生命周期锁确认中断, 不仅凭 PID 或时间推测; 异常退出或缺失结束帧不显示为已成功
- 页面只预览前 50000 字符, 单请求 JSONL 导出在服务端逐页读取并施加 64 MB 总预算, 浏览器下载仍需接收有界 Blob
- 口令/认证参数及常见凭据文本脱敏, 二进制和内嵌 base64 只保留省略/引用说明; 诊断正文仍属于敏感业务资料, 沿用对应服务认证

### SDK 边界的前台成本

每组 1000 次, 相同固定返回值, 开启组分批排空写入队列, 后台排空时间不算作 SDK 前台耗时

| 模式 | P50 | P95 |
| --- | ---: | ---: |
| 直接调用替身 | 0.20 μs | 0.30 μs |
| 建立请求边界, 高级记录关闭 | 30.40 μs | 41.10 μs |
| 高级记录开启 | 134.20 μs | 384.90 μs |

### 实际会话执行

每组运行 30 个真实 `AsyncSimpleSession.run`, 每请求两次 SDK 调用和一次工具执行, 三组历史增长方式相同; 基线绕过 SDK 诊断包装且不建立诊断请求作用域, 其余业务使用相同版本

| 模式 | 请求 P50 | 请求 P95 | 事件循环延迟 P95 | 采样进程 RSS 峰值 |
| --- | ---: | ---: | ---: | ---: |
| 基线 | 40.26 ms | 50.88 ms | 4.99 ms | 183.88 MB |
| 关闭 | 43.18 ms | 49.06 ms | 5.04 ms | 189.26 MB |
| 开启 | 42.69 ms | 47.88 ms | 10.91 ms | 192.44 MB |

开启组请求耗时没有显著放大, 不能据单次结果宣称更快; 事件循环 P95 延迟有增加, 需要在真实服务器负载下继续观察

RSS 是同进程顺序执行的 5 ms 采样峰值, 包含客户端/业务库/缓存及前序分配, 不是每组独立进程的净增加, 也不是严格峰值上界

### 同语料实际 SQLite 增长

每请求两个事件, 十条实际输入消息含稳定历史, 对照原样整条 JSON 与当前生产共享结构; 两组均开启 tracemalloc, 使用 64 条事件短事务

| 请求数 | 事件数 | 原样 JSON SQLite | 当前共享 SQLite |
| --- | ---: | ---: | ---: |
| 100 | 200 | 0.979 MB | 0.344 MB |
| 1000 | 2000 | 9.622 MB | 2.421 MB |
| 10000 | 20000 | 96.125 MB | 23.577 MB |

一万请求减少约 75.47% 文件占用; WAL 在测试连接关闭后为 0, 不代表在线高写入时没有 WAL

相同一万请求的追加耗时: 原样 3.72 秒, 当前共享 15.57 秒; 当前方案包含对象/上下文/请求/事件/来源/引用索引, 并付出摘要和压缩成本, 不声称写入比单表 JSON 更快

编码阶段 tracemalloc 峰值约 1.16 MB, 追加前后 RSS 差约 1.73 MB; 合成语料在采样前已建好, 这些值不包含输入语料自身, 不代替大正文和并发导出的进程峰值

| 一万请求后的懒读取 | P50 | P95 |
| --- | ---: | ---: |
| 上下文目录 50 项 | 8.73 ms | 9.66 ms |
| 请求摘要 50 项 | 1.62 ms | 5.22 ms |
| 单请求事件 | 0.93 ms | 6.36 ms |
| 单份输入还原 | 1.77 ms | 7.83 ms |

同轮初版目录实现一万请求 P50 约 256 ms; 改为从上下文关联索引开始查询后降至约 8.73 ms

Astro 旧样本的 95.87% 节省与这里的 75.47% 属于不同语料, 不互相替代; 本报告不作为公网真实网络或服务器磁盘性能承诺

## 展示与问题分类优化 (2026-10-26 本轮)

本节为后续界面优化的独立验收, 上文全量测试和性能数据属于前一轮, 不作为本轮重新执行的结果

### 展示行为

- 请求卡片初始收起, 展开后的事件也只显示标题; 原始 metadata, 事件 ID 和父步骤放在默认收起的技术信息中
- 工具名和实际请求模型名直接进入中文事件标题; 请求列表显示短 ID, 完整 ID 可在请求信息中查看
- 节点和请求使用四边外框及辅助文字标签, 深浅色主题均支持: 蓝色正常, 黄色调用或业务问题, 红色系统故障, 灰色等待/取消/未分类
- 展开全部只展开当前已加载节点, 不读取正文; 正文槽位仍需主动点击, 页面仅保留最近一份正文缓存
- 事件分页与后续事件刷新保留已有展开状态和正文缓存, 新节点保持收起; 重新关闭再打开整条请求时重新初始化
- 正文请求在途时收起节点或全部收起, 迟到响应只更新缓存, 不重新展开正文

### 分类依据

| 证据 | 级别 | 说明 |
| --- | --- | --- |
| 参数绑定失败, 非法工具调用, 工具名不存在 | warning / 黄色 | 模型调用问题, 不靠 TypeError 名称猜测 |
| 工具返回明确的权限拒绝, 版本冲突等 | warning / 黄色 | 与模型参数错误使用不同 error_kind |
| 工具内部执行异常, SDK 请求失败/超时, 其他捕获到的执行异常 | error / 红色 | 实际异常边界或结构化系统错误码 |
| 未识别的顶层 ok=false | warning / 黄色 | 标记未分类失败, 不冒充已确认的参数错误 |
| 审批等待, 用户取消, 跳过 | info / 灰色 | 中性状态不覆盖此前已发生的问题 |
| 旧事件缺少明确分类依据 | unknown / 灰色 | 不扫描正文猜测; 有明确错误码的旧事件仍可分类 |

工具分类只读取约定的顶层状态和错误码, 不把任意嵌套 JSON 中的 ok=false 当成失败, 不接受工具结果自报的日志级别

执行状态与问题级别独立: 参数修正后成功仍显示已完成且保留黄色, 内部错误后恢复成功仍显示已完成且保留红色; 不改变原工具返回或审批行为

请求最高级别随事件追加维护, 列表不为颜色扫描整条链路或解码正文; 独立诊断库版本从 1 升到 2, 只增加可空汇总列, 旧请求汇总保持未分类, 不修改业务数据库或批量回填历史正文
