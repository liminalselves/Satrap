# 向量库格式升级与恢复

新版 `DataBase` 把文档、元数据、原始向量和集合修订号放在同一个 SQLite 事务中。向量采用小端 float32, 归一化仅用于派生 FAISS 索引。SQLite 提交后, 即使索引写入失败, 添加操作也返回已提交的文档数; 后续搜索会重建索引, 不应因缓存日志而重复提交同一批文档。

索引文件使用稳定集合 ID 和修订号命名。旧集合名 `a/b` 与 `a_b` 不再共享索引文件。多个进程通过 SQLite 写事务串行化源数据变更, 读取在同一数据库快照中匹配索引与文档。每个集合通常保留最新两个版本缓存; 被其他进程打开而无法删除的旧缓存留待后续写入清理。

## 升级旧库

必须先停止使用该目录的所有旧版读写进程。新版不会隐式修改旧格式数据库, 打开旧库时会给出维护迁移提示。

在 UTF-8 Python 环境中, 对明确选定的向量库目录执行:

```python
from satrap.core.database import DataBase

report = DataBase.migrate_legacy(r"F:\选定的向量库目录")
print(report)
```

迁移会在库目录下建立唯一的 `migration-backup-*` 目录, 保存 SQLite 一致性备份及旧 `.faiss` 文件。随后在单个事务内升级架构, 按文档 ID 恢复旧索引向量, 并保存迁移报告。旧索引中存储的是归一化向量, 恢复后保持原有余弦相似度语义, 无法恢复归一化前的模长。

若旧索引已被覆盖、缺失或损坏, 迁移不会丢弃文档。`missing_document_ids` 会列出缺失向量的记录, 相应集合搜索抛出 `VectorDataUnavailable`, 不返回误导性的空结果。原始备份和旧索引都保留。

对于缺失记录, 从 SQLite 读取对应文档, 使用原 Embedding 模型与维度显式重新生成向量, 再调用:

```python
db = DataBase(r"F:\选定的向量库目录")
missing_ids = db.missing_vector_ids("集合名")
db.repair_missing_vectors("集合名", missing_ids, regenerated_vectors)
```

`regenerated_vectors` 必须与 `missing_ids` 一一对应。该接口拒绝覆盖已有完整向量。迁移和补齐接口不会自行访问外部模型 API。

迁移事务中断时架构与数据会回滚, 可以重试。已经升级完成时再次迁移只返回状态及缺失 ID, 不重复导入。若迁移报告写盘失败, SQL 可能已经提交; 重新调用迁移入口核对 `already_migrated` 和缺失 ID, 备份目录仍保留。

验收时核对集合数、文档数、缺失向量清单, 并对各集合执行搜索、重启和删除隔离检查。确认应用正常运行前保留备份。需要回退旧版时, 停止新版写入并恢复完整迁移前备份; 不让旧程序直接写入新版数据库。

## 归档恢复重试

会话回收包的新版本记录 `records.json` 摘要。损坏内容、错误表结构、身份不匹配或缺失文件会中止恢复并保留归档。旧包仍支持结构与身份校验。

数据库恢复与恢复凭据在同一事务提交, 随后原子发布会话文件。文件发布失败时, 保留归档并报告错误; 使用同一个回收包 ID 重试可继续发布, 不会重复插入记录。恢复成功但清理失败时返回 `ok: true, cleanup_pending: true`, 重试只继续清理。该阶段可能已有数据库记录但文件尚未发布, 应完成恢复后再使用此会话。
