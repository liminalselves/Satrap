## 2. 批次 5: 对象归属、存储恢复与防重放

### B1: 转发读取必须证明来源消息与 forward_id 的关联

涉及: `onebot/admin.py`, `onebot/adapter.py`, `group_admin/tools.py` 及工具 schema

采用明确的来源消息核验方案, 不增加一个同样可伪造的 group_id 参数作为补丁:

1. `group_admin_get_forward` 增加必填 `source_message_id`, 保留 group_id 与 forward_id
2. 经当前适配器 get_msg 回源来源消息, 校验为目标群消息; 响应含 self_id/message_id 时还须与当前账号/请求 ID 一致
3. 从该消息的规范化顶层组件中提取转发 ID, 要求请求的 forward_id 确实出现在来源消息中; 不搜索任意文本, 不从嵌套节点递归推断授权
4. 回源等待后复查群范围、账号及连接代次, 不将旧账号/旧连接的证明用于新连接
5. 通过后才调用 get_forward_msg; 回包若明确携带矛盾群号/账号则拒绝, 无这些字段不构成独立授权依据

把核验封装为管理读取的公共入口, 工具不得绕过。现有入站补全使用可信入站消息本身的关联, 不要求所有内部补全都额外回源; 管理工具必须走上述带证明的入口。旧工具调用缺 source_message_id 返回明确参数错误, 不提供不安全兼容放行。

关闭条件: 允许群号+异群转发 ID、来源消息不含该 ID、错误账号、回源失败/不支持、等待中改配置均拒绝, 且 get_forward_msg 调用数为 0; 正确来源通过。覆盖同步与异步工具入口。

### B2: 降级状态持久化, 主文件与归档使用同一恢复规则

涉及: `manual_wake_store.py`, BackendManager 存储初始化/状态接口

维持现有 JSON 方案, 不为了本轮修复整体迁移数据库。新增版本化存储清单, 记录初始化状态、应存在的文件及持久降级原因; 主文件/归档的读写、归档轮转和清单更新使用同一个存储锁协调。

- 首次全新目录可以初始化; 已有合法旧版主文件/归档经完整校验后迁移, 保留 request_id、指纹和状态
- 旧目录存在 `.corrupt-*` 而无有效恢复记录时直接降级, 不能当成全新安装
- 发现主文件/归档损坏时, 先持久标记降级, 再隔离坏文件; 标记写失败则保留原文件并拒绝依赖去重的新请求
- 已初始化存储缺失应有文件, 按损坏处理; 不将“文件不存在”无条件解释为空库
- 归档解析失败不再返回空归档; 查询明确报告状态存储降级, 接受请求必须拒绝
- 清单、归档和主文件更新采用可恢复的操作顺序/事务标记; 任一写入点崩溃后只能恢复为完整旧/新状态或显式降级, 不恢复成漏记录的可写空库
- 使用文件锁保护完整读取、查重、修改和写入过程, 不只锁最后一次写; 避免并行存储实例用陈旧缓存覆盖记录
- 写入前后同步缓存语义, 落盘失败不能对查询展示尚未持久确认的终态

恢复入口仅允许验证并恢复主文件和归档一致的完整记录集, 或重新尝试读取修复后的原文件。恢复成功前一直拒绝新手动请求, 包括重启之后。此批不提供“清空历史后继续”的默认恢复按钮。普通非幂等依赖功能可继续运行, 但必须暴露记录不可用, 不能称为完整持久化。

关闭条件: 主文件损坏→隔离→连续两次重启仍降级; 归档损坏同样拒绝; 已初始化文件丢失拒绝; 原 request_id 不重新 accepted; 合法旧数据迁移不丢失; 文件锁、归档轮转各写入点故障测试不出现记录复活或消失。

### B4: 审批账本与可用请求缓存分离

涉及: `request_registry.py`, request 入站登记、admin 审批入口、存储装配

审批防重放不能只靠一个可淘汰的 OrderedDict。保留 512 条可用请求缓存用于近期操作, 另建立按适配器 ID、已绑定 self_id、请求类别、flag 摘要定位的持久账本, 复用批次 5 的持久降级/原子写原语。

- 首次登记保存不可变对象归属及首次接收时间, 重复事件不刷新身份、过期时间或消费状态
- 审批前在持久事务中原子占用, 落盘成功后才允许发网络动作; 并发至多一个成功
- available 的可审批 TTL 到期后改为 expired 墓碑; 缓存淘汰不删除账本身份
- executing/completed/unknown/expired 均不得因重投而回到 available; 进程重启的 executing 转 unknown
- 对冲突的同 key、不同群号/subtype/user_id 拒绝并记录脱敏诊断
- 未确认协议 flag 的可靠失效机制前, 不以任意本地 TTL 删除防重放身份。账本初始上限定为每实例 4096 条, 达限拒绝新登记并提示容量问题, 已登记且仍有效的请求可以完成
- 不提供自动清空账本或靠重连重新建账的路径。今后只有取得可验证的协议失效依据, 才能另行实现安全回收; 当前将满载作为明确降级, 而非悄悄牺牲防重放

账号未知时不能登记; 好友与群请求分域。Cancellation/超时/断线均保守结束为 unknown, 不遗漏 BaseException 取消路径。

关闭条件: 容量缩小反例、TTL 过期后重投、重复入站、并发审批、占用后崩溃重启、账号/请求类别冲突、账本损坏/满载均不能产生第二次写动作。测试断言动作次数, 不只检查内存状态。

## 3. 批次 6: 真实结果、引用保护与诊断后端

### B3: 根据已提交副作用裁决请求结果

涉及: `receipt.py`, `onebot/adapter.py`, `scheduler.py`, `manual_wake_store.py`

发送计划与已经提交的动作分开表示。计划段初始为 planned; 每段在 I/O 前推进 submitted, 确认后立即保存该段结果, 后续未尝试段为 skipped。不要在整轮完成前把所有段始终留在 submitted。

请求结果按同一 request_id 关联的全部业务发送尝试归并, 不仅依赖 event.last_send_receipt; 错误反馈与业务回复区别记录, 避免“错误提示发成功”覆盖业务失败。

| 取消/退出时事实 | 请求状态 |
| --- | --- |
| 确定尚未提交任何业务写动作 | failed, detail=cancelled_before_send 等明确原因 |
| 有已提交、未确认的动作 | unknown, 保留已确认段及取消原因 |
| 有已确认前缀, 其余明确失败或未提交 | partial |
| 预定业务输出全部确认 | sent |

操作已经可能提交, 即使本地没有得到回执对象, 也不能落 failed/no_response。模型调用期间工具已发送回复的场景纳入同一规则, 不以模型超时覆盖已发生的副作用。

发送子任务负责收尾其尝试记录, 与原 A3 的终态所有权一致; 外层调用方退出不抢先写终态。等待收尾有界, 超时先显示 unknown/仍在收尾, 后续同一尝试的可信确认可精化结果; 区分这种临时未知与重启后的不可确认, 不允许恢复执行或重新发送。关联尝试创建前登记好 request_id/turn_id, 避免记录线程完成与取消之间出现漏关联。

对已 accepted 的手动请求, 若发送前的必要记录无法持久化, 不继续业务发送并冒充可恢复; 普通自动回复可保留现有降级发送策略, 但需记录/展示 tracking_unavailable。重启时只有 submitted 且未确认的动作转 unknown, planned 不伪装成已经发出。

关闭条件: I/O 前取消、首段 I/O 后取消、确认一段后取消、重复取消、停止平台、模型超时但工具已写出、收尾超时、尝试落盘失败均得到上述状态; 不重复发全文, 查询与段记录一致。

### B7: 文件兼容回落保持未确认语义

涉及: `_send_file_fallback`, 回执聚合、请求状态转换、前端标签

保留一次兼容尝试, 但普通 file 段响应即使含 message_id, 也只证明消息动作返回, 不足以证明文件交付。未经目标实现验证的回落统一返回 unknown / file_delivery_unconfirmed, 保留传输层确认信息, 禁止映射为 sent。

此 unknown 沿用停止后续段、禁止兜底全文重发的策略。Plain/File/Plain 中最后一段不发送, 第一段确认保留, 总结果标有已确认部分的 unknown。回落明确被平台拒绝可为 failed; 未来经具体实现版本验证的兼容路径才可升级确认语义。本轮不臆断旧 file 段必然失败。

关闭条件: 缺上传动作+普通消息成功仍为 unknown; 管线、持久化、工具返回与 UI 均不显示已送达; 混合链顺序、未发后缀、确认前缀和同代次能力缓存均可验证。

### B5: 扫描不完整必须阻止 ASR 删除/重命名

涉及: `asr_references.py`, ModelConfigManager、control/CLI 错误映射

采用显式扫描失败异常, 包含扫描来源的脱敏定位。以下情况不得继续返回“无引用”: 已存在文件无法读取/解析、插件 schema 无法解析、SQLite 锁定/损坏/查询失败、覆盖 JSON 非法。

仅明确不存在且在契约上允许不存在的来源可当作空集合。对旧版数据库缺少覆盖表, 先核对已知 schema 版本确实不支持该表, 否则按扫描不完整处理。不能把所有 SQLite 错误都当作“没配置”。

检查正常且有引用返回现有 config_in_use; 扫描不完整返回独立 asr_reference_scan_failed 及可理解的原因, HTTP 使用 503, CLI 返回非零状态, 不伪称已经找到具体引用。扫描通过与配置变更之间须复查所依赖配置修订, 或进入共同配置变更锁, 避免扫描期间新增引用后仍删掉配置。

关闭条件: 平台/插件全局/会话覆盖三种真实引用仍阻止变更; JSON 错误、读权限错误、数据库锁定、插件元数据损坏均不改变模型配置; 无引用正常删除; 直接 checker 抛错与内部来源失败均覆盖。

### B10 后端: 按请求关联全流程诊断

涉及: scheduler、attachments/input_projection、发送尝试查询、HTTP API

将 WakeRejectionLog 扩展为通用的有界请求诊断, 保留旧拒绝记录接口兼容。记录 adapter_id/self_id/request_id/session_id、阶段、reason_code、状态、时间、附件失败类型、截断说明、关联 turn_id, 不保存音频、正文、密钥或供应商原始响应。

- 在决策、限流、补全结束、模型结束和发送收尾位置采集, 普通自动事件与手动事件共用
- 附件失败时后续模型仍可执行, 因此阶段失败与最终发送结果分别展示, 不压成单一 failed
- 近期高频诊断按每实例 256 个请求有界保存, 支持浏览器刷新后的查询; 手动请求及已提交发送尝试继续使用持久账本, 不能因诊断环形淘汰而丢失幂等依据
- 增加列表和单请求详情查询, 按适配器/请求/阶段筛选, 返回分页或明确上限; 沿既有管理认证通路
- 记录入口不执行阻塞磁盘操作; 普通诊断丢失/不可用明确标识, 不拖垮消息处理

关闭条件: 未执行投影的拒绝、普通语音转录失败、附件部分失败、普通回复 partial/unknown、手动请求均能查到相应阶段; 查询中无正文/凭据, 容量有界, 适配器过滤准确。

## 4. 批次 7: 配置与真实决策一致

### B6: 有效零值先于到期补偿判断

涉及: wake_window/wake_policy、策略解析、dry_run

保持既有优先级: 显式 wake_message_threshold 优先于 wake_talk_value 映射, 未设置两者时使用默认值。先解析频率模式的有效阈值和来源, 若有效来源是 talk_value 且值为 0, 正常与 deadline 路径均不触发; 最长等待不得绕过关闭。明确 @、关键词及手动唤醒不受自动频率关闭影响, necessity 保持既定语义。

不更改现有平台→时段→群的逐字段合并规则。若合并后仍有显式阈值, talk_value=0 并非有效关闭; UI/试算必须显示“被显式阈值覆盖”, 不继续把该字段状态单独标成“自动参与已关闭”。需要禁用全部自动参与时使用既有 wake_mode=explicit。

关闭条件: 零值+max_wait 的审计反例不触发; 正值到期仍触发; 显式阈值+零值遵守优先级且原因准确; @/手动/necessity 不回归; 真实管线与 dry_run 一致。

### B10 配置: 平台字段可编辑、可保存、实际生效

补平台级 input_text_limit、input_media_limit、wake_talk_value 控件、默认值提示、范围校验和往返转换。输入预算保留仅平台级的约束, 不加入群/时段覆盖键。

平台表单中 talk_value 允许留空表示未设置, 0 必须按数字保存而非删除。明确展示与显式阈值的优先级。将三个新增键纳入热更新键集合, 保存后准确区分 saved_revision/active_revision, 不因这些逐事件配置变更无谓重建连接。

策略来源作为独立解析结果提供给试算/预览, 包含每字段的平台默认、时段规则索引或群覆盖来源, 以及映射为何生效/被覆盖。不把诊断来源字段混入持久化 settings。

关闭条件: 新建、编辑、清空、0 值、别名平台、未知扩展字段保留均往返正确; 热更新后下一事件使用新预算/频率, 已冻结事件保持其原快照; 不发生不必要的连接重建。

## 5. 批次 8: 编辑安全与可见结果

### B8: 草稿行由编辑表单持有, 校验不删除行

涉及: WakeOverrideEditor、wakeOverrides、Platforms、FormModal

群/时段原始行草稿提升至平台编辑表单持有, 与初始快照一起参与 dirty 比较。每行使用稳定本地 row_id, 不以数组 index 作为唯一身份。只在打开另一平台、明确重置或保存成功时重建草稿, 取消“父 value 每变一次即 effect 覆盖本地 rows”的同步方式。

转换函数返回 `{value, errors}` 而不是 silently continue。群号空/非法/重复、时间无效/相等均保留行并给字段错误; 新增全空占位行也纳入草稿, 保存时要求补全或明确删除。完整且全部继承的行允许规范化为不写覆盖, 但不在输入过程中消失。

保存与试算使用同一校验结果; 有错误阻止提交, 后端仍再次校验。恢复继承、删除行是显式用户操作。草稿不写 localStorage/sessionStorage, 避免包含平台凭据。

关闭条件: 已有群号清空再输入、重复群号、已有时段暂时无效、最后字段改继承、删除中间行、新增未完成行均不误删/串行; 服务端错误、修订冲突保留全部草稿; 界面无错误时才提交规范化值。

### B9: 使用数据路由的统一离开拦截

已核对本地安装依赖导出 createBrowserRouter、RouterProvider、useBlocker, 不需要升级路由包。

将 main.tsx 的 BrowserRouter 和 App 内 Routes 转为等价的数据路由配置; 保留现有 URL、/chat 独立布局、管理页 AppLayout、懒加载及启动认证顺序。仅调整路由装配, 不引入额外页面加载协议。

useDirtyGuard 接入 useBlocker, 同时保留 beforeunload。Modal 关闭、站内链接、浏览器前进/后退共用一套放弃/继续编辑语义; blocker.reset 保持原页面与草稿, proceed 仅在用户选择放弃后执行。避免重复确认、重复后退和用 pushState 人工来回跳转补救。
